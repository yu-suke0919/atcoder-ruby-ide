# 開発・テスト速度の改善

Ruby 削減とテスト速度改善を行った PR #5 の方針・測定記録。現在の実行手順は [README](../README.md)、テスト構成は [構成と検証方針](architecture.md)、機能追加ごとの結果は [検証記録](verification.md) を参照する。

資料 → 失敗するテスト → 最小実装 → 不要コード・資料矛盾の確認の順に進める。

## 受入条件

- RubyInstaller の SHA-256 と未管理フォルダーの保護を維持する。新規展開・管理済みキャッシュ再利用の両方で share/・include/ がなく、bin/・lib/・LICENSE と退避した Ruby の COPYING・LEGAL が残る。
- Ruby の起動・JSON・BigDecimal など同梱拡張が Windows で動く。削減前の 19,696 ファイル・102.71 MiB を基準として実測する。
- Ruby の内容走査は取得元 1 回と、ポータブル GUI 後の配布対象 1 回に整理する。NSIS は exe と主要ファイルの存在を確認する。
- Windows の全 GUI テストは 1 周とし、NSIS は実インストールとアプリ起動・サンプル・JSON・同梱 Ruby の確認に絞る。
- Linux で本番 renderer.js / bridge.js を使い、実 Ruby・Rust の実行とファイル操作を通す。同じ GUI 受入ケースを使い、Tauri 通信・ウィンドウ操作・ファイル選択と破棄確認への応答をテスト側で差し替える。後から追加した問題取得テストを含む現在の検証範囲は、構成と検証方針を参照する。
- 初回セットアップ後の Linux の GUI テスト時間、Windows 各工程、配布容量を記録する。過去の検証記録の数値は当時の測定として維持する。

## レビュー後の補強

- `E2E_RUNNER=browser` / `native` で明示選択できるようにする。未指定時は従来どおり Windows が native、それ以外が browser。不正な値はエラーにし、native は Windows のみで利用する。
- Ruby のマニフェストは通常ファイルとディレクトリだけを受け入れ、シンボリックリンクなどは内容を読む前に拒否する。
- stdio ホストは通常の EOF に加え、不正な入力による巻き戻しでも実行停止・終了待機・一時ファイル削除を行う。stdout の切断で送信スレッドが panic しないようにする。
- ホストの事前ビルドと直接起動は既存の構成を維持し、同一 Node プロセスではビルドを共有する。ワークスペースの target / `CARGO_TARGET_DIR` と Windows の `.exe` を考慮する。
- HTTP 配信は画面が使う資産の許可リストを維持する。新しい ES モジュールも明示追加し、汎用のパス解決やファイル配信機能は追加しない。
- 実行監視の共通ヘルパーは追加しない。現在の `PreparedRun.execute()` と本番側のスレッド起動エラー処理を維持し、テスト用の都合で本番 API を増やさない。

リンク混入、EOF・不正入力時の実 Ruby の後始末、stdout 切断の回帰テストを追加した。
Linux Cloud の Rust 17 件・Node 11 件（サブテスト含む）と、`E2E_RUNNER=browser` で共通 GUI 23 件が成功した（全 GUI 約 18.2 秒）。
当時の最終コミットの両 OS の CI と Windows の GUI・配布検証は [PR #5 の Checks](https://github.com/yu-suke0919/atcoder-ruby-ide/pull/5/checks) を参照する。

## NSIS の検証境界

Tauri は NSIS 内の exe に配布形式識別子 `__TAURI_BUNDLE_TYPE_VAR_NSS` を書き込み、単体 exe は `..._UNK` を持つ。
この正規の違いがあるため、両 exe のバイト完全一致を要求しない。インストール済みアプリの起動・同梱 Ruby の解決・サンプルと標準ライブラリの実行で確認する。
Ruby の配布ファイル自体は、準備済みランタイムと GUI 後のポータブル内容を照合する。

## 出力上限のGUIテスト

出力上限の確認は、1 MiBを超えるASCII文字列を一度にSTDOUT.writeする。小さなputsを繰り返す方式では、Ruby・テスト用通信・ブラウザーの負荷により、上限到達前に時間制限と競合し得る。GUIでは停止理由・比較なし・確定出力がちょうど1 MiBであることを確認する。実行時間と出力上限の設定、およびRustの実プロセスによる停止テストは維持する。

通知コールバックを時間制限より長く待機させる実プロセスのテストで、通知待ちが受信と停止判定を妨げないことを確認する。先頭の小さなチャンクで通知が止まっても出力上限で停止し、Rubyが正常終了していれば通知待ちだけで時間制限に変わらないことを確認する。ASCIIの上限出力と、切り詰めのない日本語出力では、通知されたバイト列と確定したstdout／stderrの一致も確認する。GUIの制限値や期待する停止理由は緩めない。
