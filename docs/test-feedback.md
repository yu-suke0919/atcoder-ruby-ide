# 開発・テスト速度の改善

資料 → 失敗するテスト → 最小実装 → 不要コード・資料矛盾の確認の順に進める。

## 受入条件

- RubyInstaller の SHA-256 と未管理フォルダーの保護を維持する。新規展開・管理済みキャッシュ再利用の両方で share/・include/ がなく、bin/・lib/・LICENSE と退避した Ruby の COPYING・LEGAL が残る。
- Ruby の起動・JSON・BigDecimal など同梱拡張が Windows で動く。削減前の 19,696 ファイル・102.71 MiB を基準として実測する。
- Ruby の内容走査は取得元 1 回と、ポータブル GUI 後の配布対象 1 回に整理する。NSIS は exe と主要ファイルの存在を確認する。
- Windows の全 GUI テストは 1 周とし、NSIS は実インストールとアプリ起動・サンプル・JSON・同梱 Ruby の確認に絞る。
- Linux で本番 renderer.js / bridge.js を使い、実 Ruby・Rust の実行とファイル操作を通す。同じ GUI 受入ケースを使い、確認ダイアログの返答だけをテスト側から与える。
- 初回セットアップ後の Linux の GUI テスト時間、Windows 各工程、配布容量を記録する。過去の検証記録の数値は当時の測定として維持する。

## 検証結果

Linux Cloud（2026-10-26、Node.js 24、Rust 1.99.1、Ruby 3.4.12、システム Chromium 154）で確認。

| 検証 | 結果 |
| --- | --- |
| `npm test` | Rust 17 件・Node 5 件が成功 |
| `npm run test:e2e` | 本番 Rust コア＋実 Ruby を通る共通 GUI 23 件が成功、準備後の全件 18.4 秒 |
| サンプルの UI 1 ケース | 約 1.0 秒（テストコマンド全体） |
| Ruby 削減 | 19,696 → 2,587 ファイル、107,695,373 → 45,837,438 bytes（102.71 → 43.71 MiB） |
| ライセンス | 元の LICENSE・lib 内の notices と、share から退避した COPYING / COPYING_ja / LEGAL を保持 |
| Windows CI | PR でビルド・ポータブル GUI 23 件・NSIS アプリスモーク・容量測定を確認する |

初回の Rust ホストのコンパイルは約 1.6 秒。この計測では事前導入済みの Chromium を使用したため、ブラウザー取得・OS 依存の導入時間は含まない。
5 秒の実時間タイムアウトと子プロセス終了の確認も省略していない。Cloud でブラウザー起動が制限される場合は通常の実行権限を利用する。
Windows の実測結果と配布容量は CI 完了後に追記する。

## NSIS の検証境界

Tauri は NSIS 内の exe に配布形式識別子 `__TAURI_BUNDLE_TYPE_VAR_NSS` を書き込み、単体 exe は `..._UNK` を持つ。
この正規の違いがあるため、両 exe のバイト完全一致を要求しない。インストール済みアプリの起動・同梱 Ruby の解決・サンプルと標準ライブラリの実行で確認する。
Ruby の配布ファイル自体は、準備済みランタイムと GUI 後のポータブル内容を照合する。
