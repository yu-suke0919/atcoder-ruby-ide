# 複数サンプル

サンプルは問題ごとに持ち、その問題のすべての解答ファイルで共通に使う。画面の配置は[画面の仕様](ui.md#中央実行ボタンとサンプル)を参照する。

## サンプルと実行

- サンプルは 1〜100 件。入力・期待出力・比較の有効状態・実行結果を個別に保持する。ページから読み取ったサンプルのタブと、「＋」で追加したタブを並べる。追加時は空入力・空期待出力・比較有効とする。
- 「実行」と Ctrl+Enter は、開いているファイルを選択中のサンプルで実行する。「全件実行」は表示順に既存 Runner を呼ぶ。同時実行は 1 件。実行・全件実行・停止のボタンはコード欄の下に浮かせて置く。
- 全件実行の開始時にコード・全サンプルの入力・期待出力・許容誤差を固定する。実行中も編集とサンプルの切替は可能だが、サンプルの追加・削除、ファイルの追加・削除・切替、問題の切替はできない。
- 各サンプルの打ち切りは[問題に応じて5〜30秒](atcoder-runtime.md#実行の打ち切り時間)とし、全件実行の開始時に問題の制限値を固定する。入力・出力上限と比較ルールは既存どおり。エラー・時間制限・出力上限・Windowsのメモリ上限は記録して次へ進む。手動停止と終了操作は現在の Ruby と残りの実行を中止する。
- 入力側に問題の時間・メモリ制限、出力側に実際にかかった時間を表示する。実行開始時の制限値を超えたサンプルに「制限超過の可能性」を表示する。比較結果とは独立し、編集による無効化や制限値の読み取り直しは[問題の制限値](problem-library.md#問題の制限値)に従う。保存対象には含めない。
- 結果の枠に実際の出力、その下に折りたたんだ標準エラーを表示する。判定（一致・不一致・判定なし・未実行）はサンプルのタブの色で示し、実行済み数・一致・不一致・エラー件数を表示する。未実行を一致に数えない。
- コード・実行するファイルが変われば全サンプルの判定を無効にする。サンプルの編集はそのサンプルだけ、許容誤差の変更は全サンプルを無効にする。実行中に変更しても古い実行の判定を復活させない。
- 最終 1 件は削除できない。最小画面 1280×720 と大きな行高でも編集・入力・結果・ボタンを利用できる。

## 問題ごとの誤差許容

- 問題ごとに「誤差を許容」を選び、許容誤差εを設定できる。比較が有効なすべてのサンプルに適用する。選択時の初期値は1e-6。εは0より大きい有限の数とし、未入力・不正な値を厳密比較へ黙って戻したり保存したりしない。
- 数値トークンの比較と不一致位置は[比較ルール](comparison-details.md#誤差許容)に従う。実行開始時にεを固定する。設定変更は全サンプルの判定・不一致詳細・時間超過の注意を無効にする。実行中に変更しても古い判定を復活させない。
- 境界値・非有限値・Unicode・異なる列位置、実行中の編集、1280×720をRust・Node・両OSのGUIで確認する。

## 作業領域への保存

- サンプル（入力・期待出力・比較の有効状態）と許容誤差は、問題の作業領域の`cases.json`へ自動で保存する。結果・選択位置・ソースは含めない。ケースJSONの読込・保存（外部ファイル）は持たない。
- 初めて開いた問題では、ページから読み取ったサンプルから比較有効のサンプルを作る。以後は利用者の編集だけで変わり、ページの読み取り直しで上書きしない。
- 入力・期待出力・比較設定・許容誤差・追加・削除を保存の対象とする。実行とサンプルの選択は保存しない。保存の状態（保存中・保存済み・失敗）は解答と合わせて表示する。
- 保存は同じディレクトリの一時ファイルから置き換え、失敗時に既存の JSON を壊さない。失敗時は編集内容を保持して再試行できる。
- サンプルは 1〜100 件、各入力・期待出力は UTF-8 で 1 MiB 以下、JSON 全体は 16 MiB 以下。型・必須項目・範囲を Rust で検証する。読み込みは上限付きとし、UTF-8 BOM を許容する。

## サンプルの保存形式を変えるとき

[開発ルール](../AGENTS.md)と[保存形式を変えるときの方針](problem-library.md#保存形式を変えるときの方針)を`cases.json`に適用する。互換維持だけを目的とした未知項目の無視・必須項目の既定値補完や、互換のためだけに必須項目を省略可能にすることは行わない。

- 任意項目の追加では、その項目を含まない既存の`cases.json`が、定めた未設定の意味で、従来と同じ判定・表示で読めることを固定データの回帰テストで確認する。
- 編集済みの入力・期待出力・比較設定はページを読み取り直しても戻らない。旧形式が読めないことを理由に削除したり、読み取ったサンプル・空のサンプルで黙って初期化したりしない。
- 読めなくなる変更（U3bでサンプルごとの許容誤差を問題ごとへ変えるときなど）では、元の`cases.json`を消さずに残し、現行形式へ一度だけ変換する。変換できない場合は元のまま残し、その問題を開いたときに理由と、残した元ファイルの場所を示す。変換の前後で入力・期待出力・比較設定が同じであること、失敗時の保持を固定データで検証する。

## 受入条件

- サンプル別の結果、エラー・時間制限後の継続、開始時のコードと入力、手動停止後の再実行を確認する。入力検証エラーの詳細もサンプル別に保持する。
- 自動保存と復元、比較無効時の期待出力、空期待出力、BOM、不正な型・サイズ・件数、保存失敗時の保持と再試行を検証する。
- 1280×720 と大きな行高のレイアウトを確認する。Windows では同じ GUI ケースを WebView2 で実行し、NSIS スモークと配布前照合を最終 CI で行う。
- stdio ホストの EOF・巻き戻しでは Ruby の停止と待機に加えて、実行イベント送信スレッドを join する。Runner が idle になった直後も最終イベントの送信が残るため、JSON 行を途中で切らずに終了することを回帰テストで確認する。
