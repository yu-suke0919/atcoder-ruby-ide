# 問題文の数式と画像

問題文をテキスト・数式・コード例・画像の順序付きデータとして保存する。HTMLやスクリプトは保存画面へ挿入せず、表示要素はアプリが組み立てる。数式は同梱KaTeXで表示し、外部のJavaScript・CSS・フォントを取得しない。

## 取得と固定保存

- AtCoderの `var` と `\(...\)`・`\[...\]`・`$$...$$` の数式を整形する。コード例の内容は数式として扱わない。対応しない式は原文を表示する。
- `<var>` 内の旧形式の `<sub>`・`<sup>` はTeXの下付き・上付きへ変換し、`10<sup>9</sup>` を `10^{9}` として保存する。`<var>` を含む `<pre>` は `preformatted` 要素にテキストと数式を保存し、空白・改行を保持して表示する。含まない `<pre>` は従来どおりコードとして保存し、数式を解釈しない。
- `preformatted.parts` はテキストとインライン数式だけを受け入れ、本文全体の要素数・テキスト容量に含める。保存済みの本文は再解析しないため、新しい数式抽出を適用するには再取得または確認付きの1問取り直しを使う。
- 画像URLは問題URLを基準に解決し、HTTPSの `atcoder.jp`・`img.atcoder.jp` のみ取得する。認証情報・既定以外のポート・リダイレクトを受け入れない。
- PNG・JPEG・GIF・WebP・SVGを対象に、1画像2 MiB、1問20画像、画像合計8 MiBまで取得する。ラスター画像はデコードして確認し、寸法は最大8,192px、デコード用メモリは64 MiBまでとする。SVG内のスクリプト・外部参照は拒否する。HTTPの接続5秒・全体15秒は画像1件ごとに適用する。
- SVGの `href="#..."` と `url(#...)` による同一文書内のマーカー・クリップ・グラデーション参照、および内部の `<style>`・style属性を許可する。CSSはトークンとして解析し、引用符・エスケープ・コメント・CDATAを含めて検証する。外部URL、`@import`、イベント属性、スクリプト、基準URLの変更は拒否する。URL以外の文字列や計算結果を画像として解釈するCSS画像関数（`image-set` 等）は対象外とする。埋め込みHTML・画像・アニメーション要素の制限は維持する。
- 画像はbase64として本文と同じ問題JSONへ保存する。同じURLの画像は1回だけ取得する。問題JSONの上限は32 MiB、本文のテキスト・数式・コード・代替テキストの合計は1 MiBとする。
- 本文・画像のすべての取得と検証に成功してから、単問キャッシュまたは問題集原本をアトミックに置き換える。途中で画像の取得に失敗した場合はエラーを表示し、以前の保存内容を保持する。初回取得の失敗は取得済みにしない。
- 問題集は本文と画像を一緒に固定保存する。自動更新・一括更新は行わず、確認付きの1問取り直しで対象の本文・画像・サンプル原本だけを更新する。解答・編集済みケースは保持する。
- 保存済み問題の表示・画像拡大・数式表示は通信しない。保存形式を置き換え、旧形式の互換読込やデータ移行は行わない。

## 表示と検証

- 画像を問題文パネルの幅に収め、クリックまたはキーボードで拡大ダイアログを開く。閉じる・Escで戻り、コード・ケース・結果・未保存状態・本文スクロールを保持する。
- 数式・画像の更新でも非表示状態を保持する。画像読込後のレイアウト変化でスクロール位置を失わないようにする。
- Rustで抽出順・URL制限・画像形式／容量・保存原本の検証・取得失敗時の旧データ保持を確認する。GUIで数式と画像の表示、拡大・Esc・キーボード、オフライン再表示、900×650と3列配置、既存編集・実行操作を確認する。
- SVGの内部参照・内部CSSの取得検証と保存後の検証、外部参照の拒否、実際の画像デコードを確認する。入力形式は既存の積雪深・ProductのHTMLでも確認し、旧形式の添字・指数、通常のコード例、改行・空白、保存後の数式表示をテストする。
- 実サイトとの連携は `npm run test:atcoder-live` で明示実行する。画像付きABC243 Cを実際に取得し、画像データ・寸法の保存、900×650と1,440×900での表示・拡大、再取得後の解答・ケース保持を確認する。別のRustホストを通信できないテスト用プロキシで起動し、ブラウザーもオフラインにして保存済み本文・画像・解答・ケースを開く。再取得が失敗しても保存済み原本を保持することを確認する。通常のCIは実サイトへ接続しない。
