# 構成と検証方針

## 最小構成

- Tauri v2 の Rust コマンドがネイティブダイアログ、ファイル I/O、同梱 Ruby の実行を担当する。
- HTML / CSS / JavaScript は既存の画面を使う。bridge.js が Tauri の invoke / Channel と画面をつなぐ。
- コード編集は同梱CodeMirror 6で行い、editor.mjsが文書内容・読取専用状態・カーソル・変更通知を画面へ渡す。Ruby用モードと必要な拡張をesbuildで1つのES Moduleへまとめ、依存のライセンスを同梱する。CodeMirrorが生成する表示用CSSをCSPで許可し、スクリプトは同梱ファイルに限定する。
- ruby-completion.mjsが同梱の候補・定型コードとCodeMirrorの文書内単語収集を組み合わせる。補完の表示・選択・挿入はCodeMirrorに任せ、手動で開く。候補生成にRubyプロセスや外部サービスを使わない。
- ruby-methods.mjsがString・Array・Hashのメソッドと引数・説明を保持する。ruby-receivers.mjsは既存Rubyモードの字句情報を使い、直前のリテラルと、単純な直接代入に続くローカル変数の型を有界に識別する。同じ行の単純代入・自己再代入・連鎖代入の右辺や括弧内でも代入前の型を使う。コメント・文字列中の代入を除外し、未知の文やスコープ境界では推定を解除する。改行をまたぐ未完の文やdef・undef・aliasの文脈も型を確定しない。確定できなければ一般候補へ戻す。候補詳細はCodeMirrorのinfoを使い、最小画面でも領域内に収める。
- Rust の実行・ファイル操作・期待出力比較は GUI に依存しないモジュールとし、Linux でも実プロセスでテストする。
- 入力検証とファイルパスの管理は Rust で行う。手動のファイル操作はネイティブダイアログで選んだパス、問題の作業領域はユーザーデータ内の固定パスを使う。
- Electron と本番 Node.js ランタイム、旧バックエンドの二重実装は残さない。Node.js は開発・配布準備・テストに使う。

画面の CSP と Tauri capabilities で API を絞り、出力はテキストとして表示する。

## 実行・出力・停止

Ruby は shell を介さず起動する。コードを一時 UTF-8 ファイルに書き、標準入力を渡して EOF を送る。
bootstrap で標準入出力を UTF-8 binary mode、stdout / stderr を同期出力にする。
保存済みファイルの作業ディレクトリは Rust が保持するパスの親ディレクトリ、未保存時は一時ディレクトリとする。

同時実行の予約をコマンド受付時に確保し、プロセス開始前の停止も保持する。
出力は実行ごとの Tauri Channel にバイト列で送り、最後に完了またはエラーを送る。画面は TextDecoder でチャンク間の UTF-8 を維持する。
Rust は上限内の stdout / stderr を保持し、完了時の表示・比較は確定値を使う。
逐次出力の追加はテキストで行い、スクロール位置の更新は画面フレームごとにまとめる。大量出力時のチャンクごとの再レイアウトを避ける。
停止理由は最初の要求を保持する。出力上限は理由とは独立した受信バイト数で判定し、不完全な UTF-8 末尾を追加しない。
Windows は kill-on-close の Job Object、POSIX はプロセスグループを使う。親 Ruby が先に終了しても子プロセスを管理する。停止・時間制限・出力上限ではプロセス群を終了する。終了後の削除に失敗しても実行予約を解除する。
Windows の一時的な共有違反・ロック・削除競合は短い待機で最大 3 回再試行する。

異常終了時は確定したstderrから実行ソースの絶対パスに一致する最初の有効な行番号を抽出し、RunResult.errorLineで返す。ケースモデルは比較結果と同じリビジョンで位置を失効させる。editor.mjsは専用のStateFieldでエラー行を強調し、コード変更時はそのトランザクション内で強調を解除する。行番号の抽出とジャンプの仕様は[実行エラー](run-errors.md)を参照する。

Windows のデスクトップアプリは開発時・配布版とも resource directory の ruby/bin/ruby.exe を直接使い、外部の RUBY_PATH や PATH に依存しない。
Linux のデスクトップアプリと、両OSの共通テスト・ブラウザー用テストホストは RUBY_PATH または PATH の Ruby を使う。Windows CI の共通テストでは RUBY_PATH に準備済みの vendor/ruby/bin/ruby.exe を指定する。
起動時の Ruby 確認は本実行と同じ 5 秒を上限とする。確認失敗時は「Ruby を再確認」から再試行でき、確認中は重複確認と実行を抑止する。ファイル編集・保存は確認の成否に依存しない。
Ruby は SHA-256 を固定した RubyInstaller から実行用ファイルを用意する。bin/・lib/ とライセンスを保持し、share/・include/ は除外する。share 内の COPYING・LEGAL は licenses/ruby/ に退避する。ネイティブ gem のビルドと同梱オフラインマニュアルは対象外。
Rubyはconfig/ruby-windows.jsonへ検証済みの3.4系パッチを固定し、Linux CIも同じパッチを使う。update:rubyだけが公式Ruby・RubyInstallerの一覧から最新3.4.xを選択し、アーカイブとgemの準備後に固定情報を更新する。通常ビルドやアプリ利用時には最新版を探索しない。AtCoderの公開バージョンと追加gemはconfig/atcoder-runtime.jsonに残す。RubyGemsのアーカイブをSHA-256検証し、C拡張のない採用gemと依存gemをローカルインストールする。WindowsはステージングしたRubyの標準gemディレクトリへ追加してから配置し、取得元またはgem構成が変われば作り直す。Linuxはprepare:gemsで選択したRubyへ同じ構成を用意する。[AtCoderとの比較](atcoder-runtime.md)を参照する。
RunnerはCommandのenv_removeでRUBYOPT・RUBYLIB・BUNDLE_GEMFILE・GEM_HOME・GEM_PATHを子プロセスの環境から除外してからRubyを起動する。bootstrapもGem.use_paths(Gem.default_dir)で、そのRubyの標準gemディレクトリだけを探索先にし、ユーザー用gemを含めない。prepare:gemsの既定の追加先もGem.default_dirとする。

## 文書と比較状態

Rust は選択したパスと UTF-8 の読み書きを管理する。ソースは UTF-8 のファイル全体（BOM を含む）を 1 MiB 以下とし、開く時点と保存時に検証する。ソースとケース JSON は共通の上限付き読み込み・同じディレクトリの一時ファイルからのアトミック置換を使う。キャンセル・失敗時は現在のパスを保ち、読み込み時に BOM を除く。
画面は編集内容と保存済みコードを管理し、破棄する前にネイティブ確認ダイアログを表示する。
ウィンドウを閉じる際も確認し、実行中なら停止と完了を待ってから閉じる。画面再読み込みは beforeunload で未保存ソース・ケース、実行中、ファイル操作中を保護する。通常の終了確認では二重に確認しない。
画面起動時は document_new で実行停止・終了待機・保存先リセットを行い、完了するまで編集・ファイル操作・実行を抑止する。初期化に失敗した場合はエラーを表示し、操作を有効にしない。画面で保存先が未設定のときは、保存先選択を明示的に要求する。再読み込み前のファイル操作が遅れて完了しても以前のパスへ暗黙に保存しない。
表示更新と比較のリセットを分け、同じパスへの保存で結果や実行中の比較を消さない。

期待出力は null が比較なし、空文字列が空出力との比較を表す。Rust は型と最大 1 MiB を検証する。
正常終了時だけ stdout と期待出力の CRLF / CR を LF に揃え、末尾の LF を最大 1 つ除いて比較する。
Runner は最初の不一致を 1 回だけ計算し、一致判定と詳細を RunResult に載せて送る。画面は結果を再比較せず、ケースの判定と同じリビジョンで詳細も保持・無効化する。
不一致の表示はスクロール可能なダイアログに置き、Unicode スカラー値で差の前後 40 文字を表示する。本文は text node と mark で構築する。
コード・入力・期待出力・比較設定・対象ファイルが変われば未比較に戻し、古い判定を表示しない。
高さ 720px 以下は装飾的な見出しを省き、入力・期待出力・出力を最低 1 行表示する。

## ケース管理と検証

ケース JSON の型・件数・入力サイズ検証と I/O は Rust の samples モジュールを共有する。保存は一時ファイルからの置換とし、ソースの DocumentStore には触れない。
ケースモデルは保存対象の入力・期待出力・比較設定を直近保存時と比較して未保存を判定し、画面はその結果を表示する。実行結果やケース選択は保存対象に含めない。

複数サンプルの入力・結果・選択・保存済み状態と begin / finish / fail / cancel による判定遷移は DOM 非依存の sample-cases.mjs が保持する。renderer は描画とイベント、既存の run コマンドの逐次呼び出しを担当する。Rust の実行制御は変更しない。
開始時にコード・ケースを固定し、実行中は作業ディレクトリを変更する操作を抑止する。編集による判定の無効化はケースごとのリビジョンで行う。ケースの編集では、操作したフィールドだけをモデルへ反映する。textarea の改行正規化で未編集の入力・期待出力を変更しない。
JSON 読み込みと問題取得は同じケース置換の入口を使い、保存済み状態を更新するかどうかを明示する。
問題ライブラリは Rust の library モジュールが取得・HTML抽出・キャッシュ・作業領域を管理する。保存先は app_local_data_dir とし、取得データと解答を分ける。[問題の取得・保存・切替の仕様](problem-library.md)を参照する。
問題集は collections モジュールがコンテストURL・一覧・固定原本を管理し、単問の再取得から原本を分離する。画面は1問ずつ取得を依頼し、未取得分だけをキューに積む。Tauriは問題集の登録・取得をMutexで直列化し、原本は一時ファイルから上書きせず保存する。再読み込みで画面の残りキューは失われ、保存済み一覧と原本から再開する。問題集の取得で現在の文書やワークスペースは切り替えない。
確認付きの個別取り直しだけは、キャッシュを参照せずに対象1問のHTMLを取得・検証し、原本をアトミックに置き換える。取得キューと同じMutexで直列化し、問題集の一覧・他の原本・文書ストア・ワークスペースを変更しない。表示中の対象なら問題文だけを反映し、ケースの置換や結果の消去は行わない。
問題文は選択ダイアログから分離し、workspace内の常設パネルに表示する。表示元は既存の選択中のProblemのみとし、別の本文モデルやHTTP処理を作らない。開いたときだけパネルを自動表示し、表示切替ではhidden属性とレイアウトを変える。幅1,200px以上は3列、狭い画面は問題文とコードを左側の上下に配置する。本文は順序付きデータから表示要素を組み立て、数式は同梱KaTeX、画像は問題JSON内の検証済みデータを使う。本文・コード・入出力は領域内でスクロールし、実行ボタンは外側に固定する。ダイアログを開いている間だけ既存のショートカット抑止を適用する。

Linux の画面テストは headless Chromium とローカル HTTP 配信を使う。テスト専用 Rust ホストが本番の Runner・DocumentStore・RunEvent を共有し、実 Ruby・一時ファイル I/O・停止・比較を実行する。
テスト側で Tauri 通信とウィンドウ操作、ファイル選択・破棄確認への応答を差し替える。通常の GUI テストでは、問題・問題集の登録・取得・再取得・個別取り直しの成功／失敗も、必要に応じてブリッジの応答と保存データをテスト側で用意する。HTTP・HTML解析・原本保存の処理は Rust テストで検証する。JavaScript にRubyの実行制御を再実装せず、本番フロントエンドにもテスト分岐を追加しない。
Windows と Linux は同じ画面の受入ケースを使い、Windows では WebView2 と実際のネイティブダイアログを確認する。

1. Rust 共通テストで実 Ruby・停止・制限・UTF-8・ファイル操作・比較を確認する。
2. Node で Ruby の取得整合性、削減対象・ライセンス保持、展開済みランタイムの再利用を確認する。
3. Linux でも画面の編集・実行・停止・比較・保存・未保存確認・レイアウトを検証する。Linux のテスト専用ホストだけ ATCODER_IDE_UI_TIMEOUT_MS で実行上限を短縮でき、ブラウザー E2E は 4 秒を使う。本番と Windows ネイティブ E2E は実時間 5 秒を維持する。全件は数十秒を目安とし、件数と時間の実測は verification.md に記録する。
4. Windows ポータブル配布物の全 GUI テストは 1 周。NSIS 後はexe と主要ファイルの存在を確認し、アプリ経由のサンプル実行・JSON 読み込み・同梱 Ruby のパスに絞る。
5. Ruby が PATH にない条件は両 Windows 配布形態で維持する。Ruby の元ファイルのハッシュ一覧は 1 回生成し、GUI テスト後の配布対象を 1 回照合する。インストール先の全件走査や ZIP 作成時の再計算は行わない。

検査ポートは専用の環境変数を指定した場合だけ有効。通常起動では開かない。Linux のテスト専用ホストは開発依存だけを使い、配布物に含めない。
初回の Chromium・OS 依存導入と Rust ホストのコンパイル時間を、画面テスト単体の時間と分けて記録する。

E2E は各テスト前に共通リセットで初期ソース・初期ケース・空の結果へ戻し、必要な保存先と入力を各テストで準備する。Windows の終了確認は OS のウィンドウ終了要求を使い、フロントエンドの close 権限には依存しない。

Windows E2E の CDP 接続は検査ポートのブラウザー引数で有効にし、devtools feature と開発者ツール UI は配布ビルドで無効にする。
