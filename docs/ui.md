# 画面の仕様

画面の構成と操作の仕様。受入条件は[MVP](mvp.md)、取得と保存は[問題ライブラリ](problem-library.md)、サンプルは[複数サンプル](multi-sample.md)、エディタは[エディタ仕様](code-editor.md)を参照する。[ロードマップ](roadmap.md)のPhase Uで実装し、残りはU5〜U6で実装する。

## 全体の構成

1つのウィンドウを左から4列に分ける。最小サイズは1280×720。

| 列 | 内容 |
| --- | --- |
| 左端 | ホーム、登録したコンテスト・問題集のアイコン、追加（＋）、設定（歯車） |
| 2列目 | 選択中のコンテスト・問題集の問題一覧 |
| 中央 | エディタ（ファイルのタブ）、実行ボタン、サンプル・結果 |
| 右端 | AtCoderのページを表示するブラウザ |

コンテストと問題集は同じ画面で扱う。問題を選ぶと、中央と右端がその問題の内容にすべて切り替わる。起動したときはホームを開く。ホームまたは問題を開くまで、コードとサンプルは編集も実行もできない。

## 枠の大きさ

- 境目をドラッグして、次の枠の大きさを変えられる。
  - 列の境目：左端のアイコンと問題一覧、問題一覧と中央、中央と右端のブラウザ
  - 中央の境目：エディタとサンプル・結果、サンプルと結果
- 枠ごとに最小の大きさを決め、最小のウィンドウ（1280×720）でも各枠を使える大きさを保つ。ウィンドウの大きさが変わったら、比率を保って収める。
- 左端のアイコンは列の幅に合わせて拡大・縮小する。
- 変えた大きさは画面に記憶し、次に起動したときも使う。境目のダブルクリックで既定の大きさに戻す。
- ウィンドウの大きさ・位置・最大化の状態も記憶し、次に起動したときに戻す。
- 枠ごとに大きさを固定するかどうかを、後で設定から選べるようにする（[ロードマップ](roadmap.md)のPhase Dの候補）。

## 左端：ホーム

- アイコンの列の一番上にホームのアイコンを置く。非表示にはできない。
- ホームでは、問題に関係なくエディタでRubyを書いて実行できる。サンプル・期待出力との比較・誤差許容も問題と同じように使える。問題の制限値はないため、実行の打ち切りは既定の5秒。
- ホームのコードとサンプルは、問題とは別のホーム用の作業領域へ自動で保存し、次に開いたときに戻す。
- ホームを開くと、問題一覧の列には「ホーム」と表示し、問題は並べない。右端のブラウザはAtCoderのホーム（`https://atcoder.jp/`）を表示する。
- ホームを開いても、選択中のコンテスト・問題集の問題ページは閉じない。そのコンテストに戻って問題を選ぶと、同じページを表示する。

## 左端：コンテスト・問題集

- 右端のブラウザでコンテストに参加登録すると、そのコンテストのアイコンを自動で追加する。AtCoderには参加予定のコンテストの一覧ページがないため、アプリの外で参加登録したコンテストは、アプリのブラウザでそのコンテストのトップを開いたときに追加する（[参加登録の読み取り](problem-library.md#参加登録の読み取りu6a)）。「＋」でも登録できる。
- 「＋」でコンテスト（過去のコンテストの練習を含む）または問題集のURLを入れて登録する。問題URLを入れた場合は、そのコンテストを登録してその問題を開く。
- 選択中のアイコンは色を変える。
- 参加登録で追加したコンテストは、終了から1日たつとアイコンを自動で非表示にする（起動時と1分ごとに確かめる）。「＋」で登録したコンテストと問題集、自動で非表示にした後で表示に戻したコンテストは自動では非表示にしない。
- アイコンの右クリックで非表示にできる。左端のバーの右クリックで、非表示にしたアイコンを一覧から選んで戻せる。非表示にしても、解答・サンプル・提出結果は削除しない。
- 参加登録で追加したコンテストは、開始1分前に画面の一番上のバーで「<コンテスト名>があと1分で始まります（開始 21:00）」と知らせ、タスクバーのアイコンを点滅させる。帯は閉じるボタンで閉じられ、開始時刻を過ぎたら消える。知らせるのはアプリの起動中だけで、Windowsのトーストは使わない（レジストリへの登録が必要なため。U6c）。
- 参加登録で追加したコンテストが始まったら（アプリの起動中だけ）、問題一覧を取得し、最初の問題（A問題）を開く。他の問題は、問題一覧で選んだときに初めて取得する。開始の時点でアプリを起動していなかった場合は、そのコンテストを開いたときに問題一覧を取得する。

## 2列目：問題一覧

- 選択中のコンテスト・問題集の問題を公式の順に並べる。
- 開始前に参加登録で追加したコンテストには、まだ問題一覧がない。開始前に選ぶと「開始前です（開始 2026-11-07 21:00）」のように開始の時刻を出す。選んだまま開始時刻になると、問題一覧を取得してA問題を開く（選んでいなくても同じ。上の「始まったら」）。開始後に選ぶと問題一覧を1回取得して並べ、取得できなければ理由とブラウザでのログイン・参加登録の案内を出す。
- ボタンの色は、選択中、AC（緑）、AC以外の結果（黄）、ジャッジ中を区別する。
- 色の元にする提出結果は、アプリのブラウザで表示した自分の提出一覧（`/contests/<id>/submissions/me`）に載っている提出とする。提出一覧には、どこで提出したかが書かれていないため、アプリの外で行った提出も、アプリのブラウザで提出一覧を開いたときに反映される（利用者の判断、2026-11-06）。アプリが自分から提出一覧を取りに行くのは、ジャッジ中のまま離れた場合だけ。結果はユーザーデータ領域に記憶してアプリを閉じても残す。
- 1問に複数の提出がある場合、ACが1つでもあればAC、なければジャッジ中があればジャッジ中、どちらもなければAC以外とする。提出一覧は1ページに20件までで、アプリが読むのは表示したページだけ（[提出一覧の読み取り](problem-library.md#提出一覧の読み取りu5a)）。
- ジャッジ中の結果は、別の問題を開いていても問題一覧の色で更新する。ある問題を提出した後、ブラウザで結果を見ずに次の問題へ移れる。

## 中央：エディタ

- 1つの問題に複数のファイルを持てる。問題を初めて開いたとき、空のファイルを2つ用意する。ファイル名は問題の表示番号に`_1`・`_2`を付けたもの（例：`A_1`、`A01_1`）。ホームでは`home_1`・`home_2`。
- タブの「＋」でファイルを追加する（次の番号の名前）。タブの右クリックで名前の変更・コピー・削除ができる。コピーは同じ内容のファイルを次の番号の名前で作って開く。削除はアプリ内のダイアログで確認し、最後の1つは削除できない。名前は英数字・`_`・`-`の1〜40文字。数の上限は設けない。
- タブを切り替える前に、開いているファイルを保存する。全件実行の間はタブの切り替え・追加・削除・名前の変更はできない。
- 実行するのは、開いているタブのファイル。
- 空のファイルを作るとき、問題の入力形式から読み込みのコード（例：`a, b, c, d = gets.split.map(&:to_i)`）を入れる（[読み込みのコードの生成](problem-library.md#読み込みのコードの生成)）。対応できる形はできる限り広げ、形が判断できない場合は何も入れない。利用者が書いたコードは上書きしない。縦に並ぶ入力は最初からループで1行ずつ読む形で入れ、エディタの右端の切り替えボタンで配列に入れる形と入れ替えられる。
- 既存の作業領域の`solution.rb`は、最初のファイル（例：`A_1`）として扱う。この変換は[開発ルール](../AGENTS.md)の「移行は追加しない」の例外として利用者が決めたもので、元のファイルを消さずに一度だけ行う。
- 解答は作業領域へ自動保存する（[ロードマップ](roadmap.md#確定した方針)）。
- エディタの編集支援（色分け、補完、検索・置換など）は今の機能を維持する。

## 中央：実行ボタンとサンプル

- 実行・全件実行・停止のボタンは、コード欄の下側に浮かせて置く。
- サンプルは問題ごとに全ファイルで共通。ページから取得したサンプルのタブと、「＋」で追加したタブを並べる。「削除」で選んでいるサンプルを削除する（最後の1つは削除できない）。
- 各サンプルのタブは入力と期待出力を持つ。結果の枠には実際の出力を表示し、標準エラーはその下に折りたたんで表示する。
- 判定（一致・不一致など）はサンプルのタブの色で示し、タブの説明に状態を出す。標準エラーは実行が失敗したときに開く。実行の案内やメッセージは下端のステータスバーに表示する。不一致の詳細（最初に異なる行・列）は今の機能を維持する。
- 入力側に問題の時間・メモリ制限、出力側に実際にかかった時間を表示する。
- 許容誤差は問題ごとに設定する。
- 比較が有効なサンプルがすべて一致した状態になったら、開いているファイルのコードをクリップボードへコピーし、実行ボタンの左に「クリップボードにコピーしました」と表示する。実行が終わって全部一致の状態なら、毎回コピーして表示する（利用者の判断、2026-11-07）。表示は、次の実行を始めるかコードを変えるまで残す。比較が有効なサンプルがない場合はコピーしない。この動作は設定でオン・オフでき、最初はオン。

## 右端：ブラウザ

- AtCoderのページを表示する。選択中のコンテスト・問題集の問題ごとに1つのページを持ち、選んだ問題のページを表示する。問題を切り替えても各ページの表示中のURLとスクロール位置はそのまま残る。問題を初めて開いたときは、その問題のページを表示する。
- 別のコンテスト・問題集を選ぶと、前のコンテスト・問題集のページは閉じる。もう一度選んで問題を開くと、その問題のページから表示する。
- ログイン・ログアウト・参加登録・提出は、利用者がこのブラウザのAtCoderの画面で行う。アプリにID・パスワードを入力・保存しない。ログイン状態はブラウザ（WebView2）のプロファイルの中だけに置く。
- 開催中のコンテストの問題は、ログインと参加登録をした状態で見る前提とする。問題を取得できない場合は、このブラウザでログイン・参加登録するよう案内する。
- アプリはこのブラウザのページから、サンプル（入力例・出力例）・時間制限・入力形式を読み取り、作業領域に保存する。読み取った後はオフラインでもサンプルを実行・比較できる。問題文はこのブラウザで読み、アプリでは解析・表示しない。
- アプリはこのブラウザで表示した自分の提出一覧から提出の結果を読み取り、問題一覧の色に反映する。
- このブラウザのページからアプリの機能（Rubyの実行など）を呼べないように分離する。

### 操作欄

- ブラウザの上側に、戻る・進む・更新のボタンと、表示中のページのURL欄を置く。操作の対象は表示中のページ（問題のページ、または問題を選んでいないときのホーム）で、履歴はページごとに別に持つ。
- URL欄は表示中のページのURLを示し、ページの移動や表示するページの切り替えに合わせて更新する。URLを入力してEnterを押すと、表示中のページでそのURLを開く。
- 開けるのは許可したドメインのページだけとする。AtCoder（`https://atcoder.jp`）は常に許可し、ほかのドメインは[設定](#設定歯車)から追加する（D5）。許可していないURLは開かず、URL欄の下に理由を表示する。ページ内のリンク・新しいウィンドウで開くリンクも同じ規則で、許可していないドメインへは移動しない。
- URL欄から開くとき、`https://`を省いたURLは`https://`を補う。

### るりまの全文検索（D3）

- 操作欄に「るりま」ボタンを置く。ボタンの色はるりまのページの題名と同じ青（`#33a`）。押すと、ブラウザの列の上から、るりま（Rubyリファレンスマニュアル）の窓がスライドしてくる。もう一度押す、窓の外の暗い部分を押す、問題・コンテスト・ホームを開くと、窓は上へ戻る。AtCoderのページは閉じない。
- 窓はエディタやサンプルの枠と同じく角の丸い形で、るりまのページの題名と同じ青で縁取る。大きさはブラウザの列の幅の8割（左右に1割ずつ空ける）、高さの9割（下に1割空ける。利用者の要望で8割から広げた）。窓の中に、上から順に、戻る・進む・更新とるりまのURL欄、全文検索の検索欄、るりまのページを収める（利用者の要望、2026-11-10）。
- 窓が出ている間は、AtCoderのページを暗くして後ろに見せる。窓が出てくるほど暗くし、出切ったときに白が灰色になる程度（黒を5割重ねる）にする（利用者の要望、2026-11-10）。ボタンを続けて押しても、窓は最後に押した向きへそのまま動き、押した回数だけ上下しない。AtCoderのページはアプリの画面に重ねた別の表示で、その上にアプリの枠や暗い膜を描けないため、窓を出すときにAtCoderのページの画像を撮って暗くして表示し、本物のページは隠す。窓を戻すと本物のページを出す。窓が出ている間、操作欄の戻る・進む・更新・URL欄は使えない。
- 窓を初めて開いたときは、Ruby 3.4のるりまのトップ（`https://docs.ruby-lang.org/ja/3.4/doc/index.html`）を表示する。次に開いたときは前に見ていたページを表示する。
- 検索欄に語を入れてEnterを押す（または「検索」を押す）と全文検索する。窓のURL欄にURL以外の文字を入れてEnterを押したときも全文検索する。
- 全文検索はGoogleで行い、検索語を`<語> site:docs.ruby-lang.org`とする。結果のリンクなどで3.4以外の版のページ（`https://docs.ruby-lang.org/ja/latest/…`・`/ja/4.0/…`など、`/ja/`の次が`latest`か数字で始まる版）を開くときは、同じ場所のRuby 3.4のページ（`/ja/3.4/…`）を開く。3.4にない（4.0で加わった）ページは見つからないと表示される。るりまの各版のページは最新版のページを正規のページ（`rel="canonical"`）としており、サイトマップも最新版だけのため、Googleは主に最新版のページを載せている（2026-11-10に確認）。`site:docs.ruby-lang.org/ja/latest/`のようにパスまで指定すると、利用者の手元のGoogleで絞り込みが効かず、無関係なサイトが並んだ（2026-11-10）。るりまの検索ページ（るりまサーチ）は名前（クラス・メソッド・ライブラリ）の検索だけになり、本文の全文検索には検索エンジンを使うよう案内しているため、Googleを使う（利用者の判断、2026-11-09）。最初の`site:docs.ruby-lang.org/ja/3.4/ <語>`は、Googleに載っている3.4のページがなく絞り込みが外れて無関係なサイトが並び、次の`<語> "Ruby 3.4 リファレンスマニュアル" site:docs.ruby-lang.org`は、載っているページの題名が「Ruby 4.0 リファレンスマニュアル」のため一致しないことがあった。
- 窓で開けるのはるりま（`https://docs.ruby-lang.org`）とGoogle（`https://www.google.com`）のページだけ。ほかのサイトへのリンクは開かない。AtCoderのページと同じく、ページからアプリの機能を呼べない。
- エディタでF1を押すと、選択している文字列（選択がなければカーソル位置の語）で全文検索する。
- AtCoderのページとアプリの画面（エディタ・サンプルなど）で文字列を選んで右クリックすると、メニューに「るりまを全文検索」が加わる。選ぶと窓を開いて検索する。右クリックのメニューはWebView2のメニューに項目を加えるもの。F1・右クリックで検索した語は検索欄にも入る。
- 検索する語は前後の空白を除いて空白をまとめ、200文字までにする。空なら検索しない。

### グラフの表示（D4）

- 上部の「Rubyを再確認」の右に「グラフ」ボタンを置く。押すと、るりまの窓と同じ位置・大きさで、ブラウザの列の上からグラフの窓がスライドしてくる。窓の縁はアプリのアクセント色（紫）。もう一度押す、窓の外の暗い部分を押す、問題・コンテスト・ホームを開くと、窓は上へ戻る。AtCoderのページを暗くして後ろに見せること、続けて押しても押した回数だけ上下しないこと、窓が出ている間は操作欄の戻る・進む・更新・URL欄を使えないことは、るりまの窓と同じ。るりまの窓が出ているときに「グラフ」を押すと（逆も同じ）、窓の中身だけを入れ替える（利用者の判断、2026-11-09）。
- 窓には、選択中のサンプルの標準入力から読んだグラフ・木を描く。窓が出ている間にサンプルを切り替える・標準入力を書き換えると描き直す。
- 読む形は2つ。辺の列は、`N M`の後の`u_i v_i`（重み付きなら`u_i v_i w_i`）の縦の並びで、木の`N`と`N-1`本の辺も含む。親の配列は`P_2 … P_N`の1行で、頂点`i`の親が`P_i`。
- 形は問題の入力形式と制約から判定する（自動）。判定の規則は[問題ライブラリ](problem-library.md#グラフの形の判定d4)にある。判定できない・違うときは、窓の「形式」で辺の列・親の配列を選び、開始行（標準入力の何行目からか）を指定する。手で指定した形は保存せず、問題を開き直すと自動に戻る。
  - 手で指定した辺の列は、開始行から、整数が2つまたは3つの行が続く限り読む。3つなら3つ目を重みとする。頂点数は現れた番号の最大。
  - 手で指定した親の配列は、開始行の値を`P_2`から順に読み、頂点数は値の数＋1。
- 頂点の番号は1から数える。辺に0番が現れたときは0から数える（頂点数はそのまま）。
- 初期は無向で、「有向」に印を付けると辺に矢印を付ける（利用者の判断、2026-11-09）。重み付きの辺は、重みを辺の中ほどに表示する。
- 木（親の配列、または連結で辺の数が頂点数−1の無向グラフ）は、根（1番。0から数えるときは0番）を上にした階層で描き、子は番号順に左から並べる。ほかは、辺をばね・頂点どうしを反発として自動で配置する。同じ入力なら同じ配置になる。
- 100頂点まで描く。超えるときは描かずに頂点数を表示する。読めない行があるときは、その行の番号を表示する。
- ホイールで拡大・縮小、背景のドラッグで全体の移動、頂点のドラッグで頂点の移動。「全体表示」で全体が窓に収まる大きさに戻す。

## 設定（歯車）

- 左端のバーの一番下の歯車で、設定のダイアログを開く。
- 全サンプル一致時のクリップボードへのコピーのオン・オフ。
- ブラウザで開けるドメイン（D5）：AtCoderのほかに右端のブラウザで開けるサイトを、一覧で追加・削除する。`kenkoooo.com`や`https://kenkoooo.com/atcoder/`のようにドメインかURLを入れて「追加」を押すと、そのオリジン（`https://`とホスト名、ポート）を一覧に加える。HTTPSのページだけで、ホスト名が完全に一致するページだけを開ける（サブドメインは別に追加する）。HTTPのURL、ホスト名のないもの、すでにある項目は加えず、理由を表示する。AtCoderは一覧の先頭に固定で表示し、削除できない。削除しても、そのドメインで開いているページは閉じず、次の移動から止める。
- 追加したドメインのページも、AtCoderのページと同じくアプリの機能を呼べない。アプリが読み取る（問題・提出一覧・参加登録）のはAtCoderのページだけ。
- 設定は、枠の大きさと同じく画面の`localStorage`（WebView2のプロファイル）に保存し、次の起動でも保つ。読めない値は既定に戻す。作業領域や提出結果とは別に置く。

ログインはブラウザで完結するため、設定には置かない。

## 持たない機能

以前の版にあり、Phase Uで削除する機能。

- 「AtCoder の問題」（問題URLを1つずつ入れて取得する画面）と単問キャッシュ
- 問題集の全問の一括取得（中断・未取得分の再開・確認付きの取り直し）。問題は開いたときと、参加登録したコンテストの開始時に取得する
- 問題文の解析と表示（問題文パネル、数式・画像の表示とその保存・検証、問題集の本文の固定保存）
- 外部ファイルの読み書き（ソースを開く・名前を付けて保存・新規、ケースJSONの読込・保存）
- 未保存の変更の破棄確認（自動保存のため。保存に失敗した場合を除く）
