# ロードマップ

実装の順番・範囲と確定した方針をまとめる。仕様は各資料が正とし、この資料には書かない。各項目は[開発ルール](../AGENTS.md)の順番（資料 → 失敗するテスト → 最小実装 → 不要コード・資料矛盾の確認）で、1項目を1つのPRとして進める。終えた項目の経緯と測定は[検証記録](verification.md)にある。クラウドセッションでの進め方は[クラウドセッションでの開発](cloud-development.md)を参照する。

## 現在地

- 最初のMVP（〜PR #34）：Rubyの編集・実行・停止、複数サンプルと期待出力の比較、誤差許容、問題の制限値の表示、問題に応じた実行の打ち切り時間、再帰スタック。資料だけの変更ではCIを実行しない。
- Phase U（画面の作り直し、U0〜U6c）：開催中のコンテストの問題はログインしないと取得できず、1問ずつURLを入れる「AtCoder の問題」も煩雑だったため、問題を読む・解く・確かめる・提出するまでを1つの画面で行う4列の画面にした（[画面の仕様](ui.md)）。調査（U0）の結論は[構成と検証方針](architecture.md#画面の作り直しの調査u0)と[問題ライブラリ](problem-library.md#atcoderからの読み取りの規約と頻度u0の調査)にある。
- Phase C（Rubyの実行とLSPをWSLへ、C0〜C5）：Windows版Rubyをやめ、WSL内のアプリ専用のディストリビューションで、AtCoderと同じRuby 3.4.5を`--jit`で動かす（[WSLのエージェント](architecture.md#wslのエージェント)、[実行環境の資料](atcoder-runtime.md)）。調査（C0）の結論は[構成と検証方針](architecture.md#rubyの実行環境の調査c0)、利用者のWSL2での確認は[検証記録](verification.md#利用者の手元での確認wsl2)にある。
- Phase D（使って困った順の追加、D1〜D5）：入力中の補完の自動表示、読み込みのコードの対応形式の拡大、るりまの全文検索、入力からのグラフの表示、ブラウザで開けるドメインの追加。
- 全体レビュー（PR #60の時点のR1〜R5、PR #64の時点のR6〜R9）への対応は[レビューで維持する修正](review.md)にある。
- 次はPhase F（整理）。

## 確定した方針

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 画面 | [画面の仕様](ui.md)のとおり、左端のコンテスト・問題集、問題一覧、エディタとサンプル、AtCoderのページを表示するブラウザの4列にする。最小サイズは1280×720 | 開催中のコンテストで、問題を読む・解く・提出する流れを1つの画面で完結させる |
| 問題の取得の入口 | 参加登録したコンテストを自動で追加し、過去のコンテストと問題集は「＋」でURLを登録する。「AtCoder の問題」（1問ずつの取得）と単問キャッシュは廃止する | AtCoderの問題はすべてコンテストに属し、コンテスト単位で扱える |
| 問題文 | アプリでの解析・表示は廃止し、右端のブラウザでAtCoderのページを読む。サンプル・時間制限・入力形式だけをページから読み取って保存する | 表示はAtCoderに任せ、数式・画像の保存や検証などの仕組みをなくす（KISS） |
| 開催中のコンテスト | 右端のブラウザでログインして使う。参加登録と提出も利用者がブラウザで行い、アプリは提出結果を読み取るだけにする。アプリに提出機能は持たない | ログインは利用者がAtCoderの画面で行うのが確実で、アプリがID・パスワードを扱わずに済む |
| ログイン状態の保存 | ブラウザ（WebView2）のプロファイルの中だけに置き、アプリのファイルには書かない。パスワードは扱わない | ブラウザと同じ扱いにし、アプリが資格情報を直接保存しない |
| ファイルの読み書き | 外部ファイルの読み書き（ソースを開く・名前を付けて保存・新規、ケースJSONの読込・保存）を廃止する。解答とサンプルはユーザーデータ領域の問題ごとの作業領域にだけ保存する | 問題単位で使うアプリで、保存先を選ぶ操作とネイティブのファイルダイアログが不要になる |
| 問題を選んでいないとき | 起動時はホームを開く。ホームでは問題とは別の作業領域でRubyを編集・実行できる。ホームまたは問題を開くまで編集・実行できない | 問題に関係なくRubyを試す場所を残しつつ、保存先を作業領域だけにして、保存先のない編集状態を持たない |
| 保存 | 解答とサンプルは作業領域へ自動保存する。未保存の破棄確認はなくす | 保存操作と確認ダイアログが不要になり、問題の切り替えも速くなる |
| 1問のファイル | 1問に複数のファイルを持つ | 別解を並べて試せるようにする。U3aより前の`solution.rb`からの一度だけの変換は、「移行は追加しない」の例外として利用者が決め、全員の変換が済んだのでF7で消した |
| 構成 | 画面・ブラウザ・作業領域・問題の取得はWindowsに残し、Rubyの実行とRuby LSPはWSL内のエージェントに任せる | ログインを含むブラウザ操作と日本語入力をWindowsで行い、RubyはLinuxでAtCoderに近づける |
| WSL | 必須とする。Windows版Rubyは削除する | 2系統の実行環境を保守しない（KISS）。Windows固有のテストも減る |
| WSL側のRuby | CIでビルドしたLinux版Rubyを、アプリ専用の小さなディストリビューション（Ubuntu 22.04の最小構成）に入れ、初回起動時に`wsl --import`で登録する。C3cからは配布物に含めず、GitHubのReleasesに置いたものを初回起動時（と版が変わったとき）にダウンロードし、アプリに埋め込んだSHA-256で確かめてから登録する | 利用者はWSLの本体だけを入れればよく、Ubuntuの導入・初回設定・aptやsudoが要らない。利用者のディストリビューションと分かれ、環境とバージョンを固定できる。配布物はアプリ本体だけになり小さくなる（利用者の判断、2026-11-02）。Windows版Rubyをアプリ内に入れる選択肢は、2つの実行環境の保守とAtCoderとの差（JIT・C拡張のgem）のため持たない |
| Rubyのバージョン | AtCoderと同じ3.4.5に合わせ、YJIT付きでビルドする | Linuxではバージョンを完全に合わせられ、AtCoderと同じ`--jit`も使える。ローカルで自分のコードを実行する用途のため、古いパッチによるセキュリティ上の影響は小さい |

WSL2はWindows 10（x64は1903・ビルド18362.1049以降）でも、Homeでも使える。CPUの仮想化機能を有効にする必要がある。

## 守ること

- 実際のAtCoderアカウントでのログイン・参加登録・提出と、WSL2での通しの動作は、クラウドセッションやCIでは確かめられない。該当するPRは、利用者が手元で確認する手順（確認項目の一覧）を本文に書く。
- 開催中のコンテストの挙動は、開催中にしか確かめられない。各PRで、確認に使った開催中のコンテストと日時を記録する。
- 保存形式を変える場合は[保存形式を変えるときの方針](problem-library.md#保存形式を変えるときの方針)に従う。
- 右端のブラウザに表示するAtCoderのページから、アプリの機能（Rubyの実行、ファイルの読み書きなど）を呼べないようにする。

## Phase F：整理（main fc65db3の全体レビュー）

全体レビューで見つかった資料の食い違い・使われていないコード・重複を整理する。挙動を変える項目（F0・F7）と変えない項目を分け、変えない項目は既存のテストを変えずに通ることを確かめる。

### F0. エージェントの準備中に閉じられるようにする

- `AgentClient`がエージェントの準備（初回のイメージの取得と`wsl --import`）を接続の排他の中で行っていたため、その間はウィンドウを閉じる操作とエージェントの有無を調べる操作が待っていた。準備を接続の排他の外で行い、閉じた後は起動しない。画面は実行中のときだけ停止を送る。
- 手元で、イメージの取得中に閉じられることを確かめる。

### F1. 資料を実装に合わせる

- 終えた項目を「これから実装する」と書いた記述と、D1（補完の自動表示）・D5（追加したドメイン）と食い違う記述を直す。仕様の資料の見出しと受入条件の表からロードマップの項目名を外す（調査と変換の節、WSLのイメージの版に入る`scripts/build-wsl-runtime.sh`が参照する見出しを除く）。
- この資料は現在地の要約と残りの項目にし、終えた項目の詳細は仕様の資料と検証記録に任せる。レビューで維持する修正から、削除した機能への対応記録を外す。
- 資料どうしのリンクと、コードのコメントが参照する資料の見出しが実在することをテストで確かめる。

### F2. デスクトップアプリをWindows向けだけにし、CIでClippyを実行する

- Linux向けのデスクトップアプリ（`--features desktop`）はどのCIでもビルドされず、Linuxの画面テストも使っていない（テスト用ホストとheadless Chromiumで動く）。Windows向けだけにし、`#[cfg(not(windows))]`の分岐と資料の記述を消す（利用者の判断、2026-11-12）。
- LinuxのジョブでClippyを実行し、警告をエラーにする。デスクトップアプリは、WebKitGTKの要らないWindowsのターゲットで確かめる。

### F3. 動かないコードと使われていないものを消す

- Runnerに残るWindowsのパス区切りと削除の再試行、C5より前のJITの調査スクリプトとそのテスト、ライブラリの外で使われない公開、使われていないCSS、配布物の照合のうちC3c以降は`runtime.json`1つしか守っていない部分。
- 使われていないCSSのクラスをテストで見つける。

### F4. 重複をなくす

- AtCoderのオリジンを1つの定数と、コンテスト・問題のURLを作る関数にまとめる。
- 画面テストで配るファイルを、手書きの一覧でなく`src/`の下から配る（D4で新しいモジュールを加え忘れ、画面テストが全滅した）。

### F5. 大きいファイルを分ける

- 画面：窓のスライド・るりま・グラフと、設定を別のモジュールにする。保存・問題を開く・実行・ファイルのタブは状態を共有するため分けない。
- Rust：WebView2だけの処理（右クリックのメニュー・ページの撮影）と、るりまの窓を別のモジュールにする。
- 移動だけにし、既存のテストを変えずに通す。右クリックのメニューと窓の背景の画像は手元で確かめる。

### F6. 画面の「ケース」を「サンプル」にそろえる

- 画面の文言とエラー文だけを変える。保存データの`cases`と要素のIDは変えない（利用者の判断、2026-11-12）。

### F7. 一度だけの変換を消す

- 利用者の作業領域はすべて変換済みだった（2026-11-12に利用者が確かめた）。
- `solution.rb`から`files/`への変換（U3a）と、`cases.json`から`samples.json`への変換（U3b）。同じPRに影響範囲と手で戻す手順を書く。

### 決めたこと

- 選択中のコンテストが終了から1日たって自動で非表示になると、開いている問題のページがすべて閉じる。これは今の仕様のままとする（利用者の判断、2026-11-12）。
