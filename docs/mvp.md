# MVP 仕様

## 目的

個人が Windows で使う、AtCoder の Ruby コードを編集・実行するデスクトップ IDE を作る。
最初のリリースのゴールは、Ruby コードを編集し、サンプル入力を与えて実行結果を確認できること。

開発は資料更新 → 受入条件のテスト → 最小実装 → 不要コード・資料矛盾の確認の順で行う。
後方互換やデータ移行は設けず、現在の仕様を満たすシンプルな構成を維持する。

## 利用の流れ

1. 起動すると、実行可能なサンプルコードと標準入力が表示される。
2. コードを編集するか、UTF-8 の `.rb` ファイルを開く。
3. 必要に応じてコードを UTF-8 のファイルに保存する。
4. 標準入力を入力し、必要なら「期待出力と比較」を有効にして期待出力を入力する。
5. 実行し、標準出力・標準エラー・終了状態・実行時間と、期待出力との一致・不一致を確認する。
6. 終わらないコードは停止でき、停止後も再実行できる。

## 受入条件

| ID | 機能 | 完成の条件 |
| --- | --- | --- |
| M01 | コード編集 | Rubyの色分け、行番号、括弧の補完・対応表示、自動インデント、選択行の字下げ・解除、入力補完・定型コード、検索・置換、Undo／Redoを使える。Tabは2スペース。詳細は[エディタ仕様](code-editor.md)を参照。 |
| M02 | 読み込み | 日本語・空白を含むパスの UTF-8 ファイルを開ける。選択キャンセル時は現在の内容を維持する。UTF-8 BOM は読み込み時に除く。 |
| M03 | 保存 | 初回は保存先を選び、以降は同じパスへ保存できる。「名前を付けて保存」もできる。キャンセル・失敗時は変更状態を維持する。 |
| M04 | 実行 | 標準入力 `1\n2 3\ntest\n` を読むサンプルを実行すると、標準出力に `6 test\n` が表示される。入力は EOF まで渡す。 |
| M05 | 出力 | stdout と stderr を分け、実行中も順次表示する。構文エラー・実行時エラー・Ruby 起動失敗を表示し、その後も実行できる。実行コードの位置が分かるエラーは、その行へジャンプ・強調できる。詳細は[実行エラー](run-errors.md)を参照。 |
| M06 | 停止 | 停止操作で実行中のプロセス群を終了し、再実行できる。既定5秒、制限既知の問題は問題の制限＋1秒（最低5秒・最大30秒）で自動停止する。 |
| M07 | 実行制御 | 同時実行は 1 件。保存済みファイルはそのディレクトリを作業ディレクトリとし、現在の編集内容を実行する。未保存時は一時ディレクトリを使う。 |
| M08 | 上限 | コード・標準入力はそれぞれ UTF-8 で最大 1 MiB。ソースの読み込み・保存も 1 MiB 以下に制限する。出力の合計が 1 MiB に達したら打ち切り、停止理由を表示する。WindowsはRubyと子孫の合計コミットを1 GiBに制限し、確保拒否を検知したら停止する。 |
| M09 | 変更の保護 | 変更済みのコードを開き直す・新規作成する・ウィンドウを閉じる際、破棄の確認を行う。拒否したら編集内容を維持する。画面再読み込みでも未保存ソース・ケースを保護する。 |
| M10 | Windows 配布 | Tauri v2 で Windows x64 用のポータブル ZIP と NSIS インストーラーを生成し、実行用 Ruby と必要なライセンスを同梱する。Ruby の別途インストールを不要にする。ZIP 版はアプリのインストールを不要とする。WebView2 は端末のものを使い、未導入時はインストーラーが取得する。 |
| M11 | 期待出力との比較 | ケースごとの期待出力を任意で指定できる。正常終了した標準出力を比較し、一致・不一致を表示する。無効時は比較せず、有効時は空文字列も期待出力として扱う。 |
| M12 | Ruby 非導入環境 | Windows の配布版は常に同梱 Ruby を直接使う。Ruby が PATH に存在せず、`RUBY_PATH` が存在しないパスを指す条件でも、実行・停止・標準ライブラリの読み込みが成功する。 |
| M13 | 複数サンプル | ケースを追加・削除・切替でき、選択ケースと全件の逐次実行ができる。ケース別の出力・判定・実行時間を保持する。エラー後も次へ進み、手動停止は残りも中止する。 |
| M14 | ケースの保存 | 入力・期待出力・比較設定を JSON に保存・読み込みできる。破棄前に未保存変更を確認し、キャンセル・不正なファイル・I/O 失敗時は内容を保持する。 |
| M15 | 不一致の詳細 | 「不一致」から最初に異なる行・列と期待値・実際値を確認できる。空白・空行・行不足を区別し、編集・再実行で古い詳細を表示しない。ケース別に保持し、最小画面でも確認できる。 |
| M16 | 問題の取り込み | AtCoder の公開問題URLから問題文・サンプルと時間・メモリ制限を取得し、ユーザーデータ領域に保存する。制限不明も有効とし、既知の時間制限を超えたケースには可能性を注意表示する。保存済み問題はオフラインで開き、問題別の解答・ケースを復元できる。切替で未保存変更を保護し、再取得は解答・ケースを変更しない。詳細は [問題ライブラリ](problem-library.md) を参照。 |
| M17 | 問題集 | コンテストURLから問題集名と収録問題を公式順で取得し、本文・サンプルを固定保存する。進捗・中断・未取得分の再試行・オフラインでの一覧切替に対応する。自動・一括の更新は行わず、取得済みの原本は対象と上書き内容の確認後に1問だけ取り直せる。解答・編集済みケースは保持する。 |
| M18 | 問題文と編集の同時表示 | 問題文を常設パネルで読みながら編集・保存・実行できる。開くと自動表示し、表示・非表示を切り替えてもコード・ケース・結果・未保存状態を保持する。広い画面は問題文・コード・入出力の3列、狭い画面は左に問題文とコードを上下配置し右に入出力を置く。900×650と大きな行高でも操作できる。 |
| M19 | Ruby実行環境の整合 | Rubyは検証済みの3.4系パッチ、採用した5つのgemと依存を固定取得して同梱する。最新パッチを開発時の更新コマンドで取得できる。オフラインで代表コードを実行でき、AtCoderとのパッチ・未対応gem・OS・JIT等の差を資料に記録する。 |

数式は整形表示し、問題内の画像を保存して拡大・オフライン表示できる。詳細は[問題文の数式と画像](problem-presentation.md)を参照する。

標準入力と期待出力は複数ケースとして手入力できる。ケースの切替で入力と結果を保持し、選択ケースまたは全件を表示順に実行する。ケースは Ruby ソースと別の JSON に保存・読み込みできる。標準入力の改行はそのまま実行に渡す。期待出力や比較設定だけの編集では、標準入力の CRLF / CR を変更しない。
比較の初期状態は無効。初期サンプルの期待出力欄には `6 test\n` を用意する。追加ケースは空入力・空期待出力・比較有効とする。
期待出力は UTF-8 で最大 1 MiB。比較時は CRLF / CR を LF に統一し、両方の末尾の改行を最大 1 つ除く。
それ以外の空白・空行・大文字小文字・数値表記は、既定の厳密比較で区別する。ケースごとに数値の誤差許容を選べる。問題固有の判定は行わない。詳細は[比較ルール](comparison-details.md#誤差許容)を参照する。
比較の対象は実行開始時の期待出力と、その実行が返す標準出力。stderr は比較しない。
エラー終了・手動停止・時間制限・出力上限・メモリ上限・起動失敗では「判定なし」とし、一致・不一致を付けない。
コード・標準入力・期待出力・比較の有効状態・対象ファイルを変更したら、比較表示を未比較に戻す。
同じパスへの上書き保存では比較結果と実行中の比較を保持する。コードを編集した場合は編集時に未比較となる。
初回保存や「名前を付けて保存」でパスが変わった場合は、実行時の作業ディレクトリが変わり得るため未比較に戻す。
保存のキャンセル・失敗では、比較表示を変更しない。
実行中に変更した場合も、完了した古い実行の判定を現在の入力に表示しない。結果のクリアでも比較表示を戻す。
期待出力欄と比較結果は、最小画面と行高が大きい場合も入力・出力・実行ボタンと同時に利用できるようにする。
コード編集欄は改行を LF に統一する。CRLF のファイルを開いた直後は変更済みとしない。
一時ファイルの削除に失敗しても実行状態は解除し、後続の実行を可能にする。
最小ウィンドウサイズ 900×650 でも、OS のフォント寸法によらず入力欄・結果欄・実行ボタンを利用できるようにする。
入力・出力の本文は領域内でスクロールし、結果パネルを実行ボタンに重ねない。
ショートカットは `Ctrl+O`（開く）、`Ctrl+S`（保存）、`Ctrl+Shift+S`（名前を付けて保存）、`Ctrl+Enter`（実行）。

画面の初期化では、既存の実行停止と文書の保存先リセットを完了してから操作を有効にする。再読み込み後の無題のソースを以前の保存先へ上書きしない。未保存ソース・ケース、実行中、ファイル操作中の再読み込みはブラウザーの離脱確認で保護する。ウィンドウ終了では既存のネイティブ確認だけを使う。

Ruby の起動確認は上限 5 秒。失敗後も「Ruby を再確認」で復帰でき、コードとケースの編集・保存は継続できる。

## 実行環境

- Tauri v2 の Rust バックエンドと HTML / CSS / JavaScript の画面を使う。
- Linux Cloud で Rust の実プロセス・ファイル I/O・比較と、headless Chromium による画面テストを実行する。
- Windows の実画面テストは WebView2 とネイティブファイルダイアログで、編集・保存・比較・停止・未保存確認を検証する。
- Windows の GUI 全件テストはポータブル版で 1 周とし、NSIS インストール後はアプリ経由のスモークテストを行う。
- Rubyは検証済みの3.4系パッチを使う。Windowsには対応する公式RubyInstaller x64を同梱し、バージョンと公式SHA-256を固定する。AtCoderの公開バージョンとのパッチ差を許容する。
- 公式と同じバージョンの追加gemを5つと依存gemを同梱する。全gemやOS・JIT・制限の一致は保証しない。[採用gemと残る差](atcoder-runtime.md)を参照する。
- share/・include/ を除外し、COPYING・LEGAL を含むライセンス資料を保持する。ネイティブ gem のビルドとオフラインマニュアルは対象外。
- Ruby は通常のユーザープロセスとして実行する。アプリはオンラインのコード実行サービスではない。
