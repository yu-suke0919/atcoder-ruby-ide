# MVP 仕様

## 目的

個人が Windows で使う、AtCoder の Ruby コードを編集・実行するデスクトップ IDE を作る。
最初のリリースのゴールは、Ruby コードを編集し、サンプル入力を与えて実行結果を確認できること。

開発は資料更新 → 受入条件のテスト → 最小実装 → 不要コード・資料矛盾の確認の順で行う。
後方互換やデータ移行は設けず、現在の仕様を満たすシンプルな構成を維持する。

## 利用の流れ

1. 起動すると、実行可能なサンプルコードと標準入力が表示される。
2. コードを編集するか、UTF-8 の `.rb` ファイルを開く。
3. 必要に応じてコードを UTF-8 のファイルに保存する。
4. 標準入力を入力し、必要なら「期待出力と比較」を有効にして期待出力を入力する。
5. 実行し、標準出力・標準エラー・終了状態・実行時間と、期待出力との一致・不一致を確認する。
6. 終わらないコードは停止でき、停止後も再実行できる。

## 受入条件

| ID | 機能 | 完成の条件 |
| --- | --- | --- |
| M01 | コード編集 | 複数行の Ruby コードを編集でき、Tab で 2 文字のスペースを挿入できる。 |
| M02 | 読み込み | 日本語・空白を含むパスの UTF-8 ファイルを開ける。選択キャンセル時は現在の内容を維持する。UTF-8 BOM は読み込み時に除く。 |
| M03 | 保存 | 初回は保存先を選び、以降は同じパスへ保存できる。「名前を付けて保存」もできる。キャンセル・失敗時は変更状態を維持する。 |
| M04 | 実行 | 標準入力 `1\n2 3\ntest\n` を読むサンプルを実行すると、標準出力に `6 test\n` が表示される。入力は EOF まで渡す。 |
| M05 | 出力 | stdout と stderr を分け、実行中も順次表示する。構文エラー・実行時エラー・Ruby 起動失敗を表示し、その後も実行できる。 |
| M06 | 停止 | 停止操作で実行中のプロセス群を終了し、再実行できる。5 秒を超える実行は自動停止する。 |
| M07 | 実行制御 | 同時実行は 1 件。保存済みファイルはそのディレクトリを作業ディレクトリとし、現在の編集内容を実行する。未保存時は一時ディレクトリを使う。 |
| M08 | 上限 | コード・標準入力はそれぞれ UTF-8 で最大 1 MiB。出力の合計が 1 MiB に達したら打ち切り、停止理由を表示する。 |
| M09 | 変更の保護 | 変更済みのコードを開き直す・新規作成する・ウィンドウを閉じる際、破棄の確認を行う。拒否したら編集内容を維持する。 |
| M10 | Windows 配布 | Tauri v2 で Windows x64 用のポータブル ZIP と NSIS インストーラーを生成し、実行用 Ruby と必要なライセンスを同梱する。Ruby の別途インストールを不要にする。ZIP 版はアプリのインストールを不要とする。WebView2 は端末のものを使い、未導入時はインストーラーが取得する。 |
| M11 | 期待出力との比較 | 1 ケースの期待出力を任意で指定できる。正常終了した標準出力を比較し、一致・不一致を表示する。無効時は比較せず、有効時は空文字列も期待出力として扱う。 |
| M12 | Ruby 非導入環境 | Windows の配布版は常に同梱 Ruby を直接使う。Ruby が PATH に存在せず、`RUBY_PATH` が存在しないパスを指す条件でも、実行・停止・標準ライブラリの読み込みが成功する。 |

標準入力と期待出力は毎回手入力し、Ruby ソースだけを保存する。標準入力の改行はそのまま実行に渡す。
比較の初期状態は無効。初期サンプルの期待出力欄には `6 test\n` を用意する。
期待出力は UTF-8 で最大 1 MiB。比較時は CRLF / CR を LF に統一し、両方の末尾の改行を最大 1 つ除く。
それ以外の空白・空行・大文字小文字・数値表記は区別する。浮動小数点の許容誤差や問題固有の判定は行わない。
比較の対象は実行開始時の期待出力と、その実行が返す標準出力。stderr は比較しない。
エラー終了・手動停止・時間制限・出力上限・起動失敗では「判定なし」とし、一致・不一致を付けない。
コード・標準入力・期待出力・比較の有効状態・対象ファイルを変更したら、比較表示を未比較に戻す。
同じパスへの上書き保存では比較結果と実行中の比較を保持する。コードを編集した場合は編集時に未比較となる。
初回保存や「名前を付けて保存」でパスが変わった場合は、実行時の作業ディレクトリが変わり得るため未比較に戻す。
保存のキャンセル・失敗では、比較表示を変更しない。
実行中に変更した場合も、完了した古い実行の判定を現在の入力に表示しない。結果のクリアでも比較表示を戻す。
期待出力欄と比較結果は、最小画面と行高が大きい場合も入力・出力・実行ボタンと同時に利用できるようにする。
コード編集欄は改行を LF に統一する。CRLF のファイルを開いた直後は変更済みとしない。
一時ファイルの削除に失敗しても実行状態は解除し、後続の実行を可能にする。
最小ウィンドウサイズ 900×650 でも、OS のフォント寸法によらず入力欄・結果欄・実行ボタンを利用できるようにする。
入力・出力の本文は領域内でスクロールし、結果パネルを実行ボタンに重ねない。
ショートカットは `Ctrl+O`（開く）、`Ctrl+S`（保存）、`Ctrl+Shift+S`（名前を付けて保存）、`Ctrl+Enter`（実行）。

## 実行環境

- Tauri v2 の Rust バックエンドと HTML / CSS / JavaScript の画面を使う。
- Linux Cloud で Rust の実プロセス・ファイル I/O・比較と、headless Chromium による画面テストを実行する。
- Windows の実画面テストは WebView2 とネイティブファイルダイアログで、編集・保存・比較・停止・未保存確認を検証する。
- Windows の GUI 全件テストはポータブル版で 1 周とし、NSIS インストール後はアプリ経由のスモークテストを行う。
- 開発環境の Ruby は現在 3.4.12。Windows には公式 RubyInstaller 3.4.12-1 x64 を同梱し、公式サイト用データで公開された SHA-256 に固定する。
- AtCoder 本番と Ruby バージョンや追加 gem が完全に一致することは、今回の MVP の保証範囲に含めない。標準ライブラリを使ったローカル実行を提供する。
- share/・include/ を除外し、COPYING・LEGAL を含むライセンス資料を保持する。ネイティブ gem のビルドとオフラインマニュアルは対象外。
- Ruby は通常のユーザープロセスとして実行する。アプリはオンラインのコード実行サービスではない。

## 次のイテレーションの候補

- 複数サンプルの保存・読み込みと一括テスト
- シンタックスハイライトと補完
- AtCoder の問題データの取得
- AtCoder 実行環境とのバージョン・gem の一致
- アプリアイコンの整備

優先順位は MVP を使ってから決める。
