# MVP 仕様

## 目的

個人が Windows で使う、AtCoder の Ruby コードを編集・実行するデスクトップ IDE を作る。
開催中のコンテストで、問題を読む・解く・サンプルで確かめる・提出する流れを1つの画面で完結させる。画面の構成は[画面の仕様](ui.md)を正とする。

開発は資料更新 → 受入条件のテスト → 最小実装 → 不要コード・資料矛盾の確認の順で行う。
後方互換やデータ移行は設けず、現在の仕様を満たすシンプルな構成を維持する。

## 利用の流れ

1. コンテストに参加登録するか、「＋」でコンテスト・問題集のURLを登録する。
2. 問題一覧から問題を選ぶ。右端のブラウザにAtCoderの問題ページが表示され、サンプル・時間制限・入力形式が読み取られる。
3. エディタで解答を書く。解答とサンプルは問題ごとの作業領域へ自動で保存される。
4. サンプルを実行し、標準出力・標準エラー・実行時間と、期待出力との一致・不一致を確認する。終わらないコードは停止でき、停止後も再実行できる。
5. 右端のブラウザで提出する。結果は問題一覧の色に反映され、その間に次の問題へ進める。

## 受入条件

Phase Uで変わる条件は、機能の欄に実装する[ロードマップ](roadmap.md)の項目を付ける。その項目の実装までは、以前の仕様のテストとコードが残る。

| --- | --- | --- |
| M01 | コード編集 | Rubyの色分け、行番号、括弧の補完・対応表示、自動インデント、選択行の字下げ・解除、入力補完・定型コード、検索・置換、Undo／Redoを使える。Tabは2スペース。詳細は[エディタ仕様](code-editor.md)を参照。 |
| M02 | 問題の作業領域 | 起動時はホームを開き、問題とは別にRubyを編集・実行できる。ホームまたは問題を開くまでコードとサンプルを編集・実行できない。1問に複数のファイルを持ち、初めて開くと空のファイルを2つ用意する。タブで切り替え、追加・コピー・削除・名前の変更ができ、開いているタブを実行する。 |
| M03 | 自動保存 | 解答とサンプルを作業領域へ自動で保存する。`Ctrl+S`はダイアログなしですぐ保存する。保存中・保存済み・失敗を表示し、失敗時は編集内容を残して再試行できる。外部ファイルの読み書きとネイティブのファイルダイアログは持たない。 |
| M04 | 実行 | 標準入力 `1\n2 3\ntest\n` を読むサンプルを実行すると、標準出力に `6 test\n` が表示される。入力は EOF まで渡す。 |
| M05 | 出力 | stdout と stderr を分け、実行中も順次表示する。構文エラー・実行時エラー・Ruby 起動失敗を表示し、その後も実行できる。実行コードの位置が分かるエラーは、その行へジャンプ・強調できる。詳細は[実行エラー](run-errors.md)を参照。 |
| M06 | 停止 | 停止操作で実行中のプロセス群を終了し、再実行できる。既定5秒、制限既知の問題は問題の制限＋1秒（最低5秒・最大30秒）で自動停止する。 |
| M07 | 実行制御 | 同時実行は 1 件。現在の編集内容を、一時ディレクトリを作業ディレクトリとして実行する。 |
| M08 | 上限 | コード・標準入力はそれぞれ UTF-8 で最大 1 MiB。解答ファイルの保存も 1 MiB 以下に制限する。出力の合計が 1 MiB に達したら打ち切り、停止理由を表示する。WindowsはRubyと子孫の合計コミットを1 GiBに制限し、確保拒否を検知したら停止する。 |
| M09 | 変更の保護 | 保存に失敗したまま問題を切り替える・ウィンドウを閉じる場合だけ、アプリ内のダイアログで確認する。拒否したら編集内容を維持する。画面再読み込みでも保存中・保存失敗の内容を保護する。 |
| M10 | Windows 配布 | Tauri v2 で Windows x64 用のポータブル ZIP と NSIS インストーラーを生成し、実行用 Ruby と必要なライセンスを同梱する。Ruby の別途インストールを不要にする。ZIP 版はアプリのインストールを不要とする。WebView2 は端末のものを使い、未導入時はインストーラーが取得する。 |
| M11 | 期待出力との比較 | サンプルごとの期待出力を任意で指定できる。正常終了した標準出力を比較し、一致・不一致を表示する。無効時は比較せず、有効時は空文字列も期待出力として扱う。 |
| M12 | Ruby 非導入環境 | Windows の配布版は常に同梱 Ruby を直接使う。Ruby が PATH に存在せず、`RUBY_PATH` が存在しないパスを指す条件でも、実行・停止・標準ライブラリの読み込みが成功する。 |
| M13 | 複数サンプル（U3b） | サンプルを追加・削除・切替でき、選択サンプルと全件の逐次実行ができる。サンプルは問題ごとに全ファイルで共通とし、タブの色で判定を示す。サンプル別の出力・判定・実行時間を保持する。エラー後も次へ進み、手動停止は残りも中止する。 |
| M14 | サンプルの保存（U3b） | 入力・期待出力・比較設定と問題ごとの許容誤差を作業領域へ自動で保存し、問題を開き直すと復元する。ケースJSONの読込・保存は持たない。 |
| M15 | 不一致の詳細 | 「不一致」から最初に異なる行・列と期待値・実際値を確認できる。空白・空行・行不足を区別し、編集・再実行で古い詳細を表示しない。サンプル別に保持し、最小画面でも確認できる。 |
| M16 | ページからの読み取り（入力形式とコードの生成はU4） | 右端のブラウザで開いた問題ページから、サンプル・時間とメモリの制限・入力形式を読み取って作業領域に保存する。読み取った後はオフラインでも実行・比較できる。利用者が編集したサンプルは読み取り直しで変更しない。ログインまたは参加登録をしていないために読み取れない場合は、ブラウザでの操作を案内する。空のファイルには入力形式から読み込みのコードを入れる。詳細は[問題ライブラリ](problem-library.md)を参照。 |
| M17 | コンテストと問題集（参加登録・通知・開始時の自動取得はU6） | 「＋」でコンテスト・問題集のURLを登録し、問題一覧を公式の順で表示する。右端のブラウザで参加登録したコンテストは自動で登録する。アイコンの選択・非表示・復元ができ、参加登録で追加したものは終了から1日で非表示にする。参加登録したコンテストの開始1分前に通知し、開始時に問題一覧を取得して最初の問題を開く。問題は選んだときに取得する。 |
| M18 | 画面の構成 | 左からコンテスト・問題集のアイコン、問題一覧、エディタとサンプル、AtCoderのページを表示するブラウザの4列に分ける。最小サイズは1280×720。ブラウザは選択中のコンテスト・問題集の問題ごとにページを持ち、ページからアプリの機能を呼べない。ブラウザの上側に戻る・進む・更新とURL欄を置き、許可したドメイン（今はAtCoderだけ）のページだけを開く。左端のアイコンを含む列と中央の枠の境目をドラッグして大きさを変えられ（アイコンは幅に合わせて拡大・縮小）、ウィンドウの大きさ・位置とともに次の起動でも保つ。 |
| M19 | Ruby実行環境の整合 | Rubyは検証済みの3.4系パッチ、採用した5つのgemと依存を固定取得して同梱する。最新パッチを開発時の更新コマンドで取得できる。オフラインで代表コードを実行でき、AtCoderとのパッチ・未対応gem・OS・JIT等の差を資料に記録する。 |
| M20 | 提出結果（U5） | 右端のブラウザで行った提出の結果を読み取り、問題一覧の色（AC・AC以外・ジャッジ中）に反映する。別の問題を開いていても更新し、アプリを閉じても残す。 |
| M21 | クリップボード（U5） | 比較が有効なサンプルがすべて一致したら、開いているファイルのコードをクリップボードへコピーする。設定でオン・オフできる。 |

標準入力と期待出力は、問題ごとの複数のサンプルとして持つ。サンプルの切替で入力と結果を保持し、選択サンプルまたは全件を表示順に実行する。標準入力の改行はそのまま実行に渡す。期待出力や比較設定だけの編集では、標準入力の CRLF / CR を変更しない。
ページから読み取ったサンプルは比較を有効にする。追加したサンプルは空入力・空期待出力・比較有効とする。
期待出力は UTF-8 で最大 1 MiB。比較時は CRLF / CR を LF に統一し、両方の末尾の改行を最大 1 つ除く。
それ以外の空白・空行・大文字小文字・数値表記は、既定の厳密比較で区別する。問題ごとに数値の誤差許容を選べる。問題固有の判定は行わない。詳細は[比較ルール](comparison-details.md#誤差許容)を参照する。
比較の対象は実行開始時の期待出力と、その実行が返す標準出力。stderr は比較しない。
エラー終了・手動停止・時間制限・出力上限・メモリ上限・起動失敗では「判定なし」とし、一致・不一致を付けない。
コード・標準入力・期待出力・比較の有効状態・許容誤差・実行するファイルを変更したら、比較表示を未比較に戻す。保存では比較表示を変えない。
実行中に変更した場合も、完了した古い実行の判定を現在の入力に表示しない。結果のクリアでも比較表示を戻す。
コード編集欄は改行を LF に統一する。CRLF を含むファイルを開いた直後は変更済みとしない。
一時ファイルの削除に失敗しても実行状態は解除し、後続の実行を可能にする。
最小ウィンドウサイズ 1280×720 でも、OS のフォント寸法によらず入力欄・結果欄・実行ボタンを利用できるようにする。
入力・出力の本文は領域内でスクロールし、結果パネルを実行ボタンに重ねない。
ショートカットは `Ctrl+S`（すぐ保存）、`Ctrl+Enter`（実行）。

画面の初期化では、既存の実行停止を完了してから操作を有効にする。

Ruby の起動確認は上限 5 秒。失敗後も「Ruby を再確認」で復帰でき、コードとサンプルの編集・保存は継続できる。

## 実行環境

- Tauri v2 の Rust バックエンドと HTML / CSS / JavaScript の画面を使う。
- Linux Cloud で Rust の実プロセス・ファイル I/O・比較と、headless Chromium による画面テストを実行する。
- Windows の実画面テストは WebView2 で、編集・自動保存・比較・停止・保存失敗時の確認を検証する。
- Windows の GUI 全件テストはポータブル版で 1 周とし、NSIS インストール後はアプリ経由のスモークテストを行う。
- Rubyは検証済みの3.4系パッチを使う。Windowsには対応する公式RubyInstaller x64を同梱し、バージョンと公式SHA-256を固定する。AtCoderの公開バージョンとのパッチ差を許容する。
- 公式と同じバージョンの追加gemを5つと依存gemを同梱する。全gemやOS・JIT・制限の一致は保証しない。[採用gemと残る差](atcoder-runtime.md)を参照する。
- share/・include/ を除外し、COPYING・LEGAL を含むライセンス資料を保持する。ネイティブ gem のビルドとオフラインマニュアルは対象外。
- Ruby は通常のユーザープロセスとして実行する。アプリはオンラインのコード実行サービスではない。
- アプリはAtCoderのパスワードを扱わない。ログイン・参加登録・提出は、右端のブラウザのAtCoderの画面で利用者が行う。
