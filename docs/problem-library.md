# AtCoder 問題ライブラリ

## 保存先と責務

Tauri の `app.path().app_local_data_dir()` を使う。Windows では通常 `%LOCALAPPDATA%\io.github.yu-suke0919.atcoder-ruby-ide`。配布フォルダーや一時キャッシュには保存しない。

```text
<app_local_data_dir>/
  library/problems/<contest-id>/<task-id>/problem.json
  workspaces/<contest-id>/<task-id>/solution.rb
  workspaces/<contest-id>/<task-id>/cases.json
```

`library` は取得した問題、`workspaces` は自分の解答とケース。再取得では `problem.json` だけを更新し、解答・編集済みケースは上書きしない。初回に空の解答とサンプルのコピーを作り、再度開くと保存済み解答・ケースを復元する。解答は通常の「保存」、ケースは「ケース保存」でこの作業領域へ保存する。問題選択中に手動でケースJSONを取り込んだ場合は、作業領域の保存済み内容との差分を未保存として扱う。

## 1問の取り込み

- 「AtCoder の問題」ダイアログで `https://atcoder.jp/contests/<contest-id>/tasks/<task-id>` を入力する。クエリ・フラグメントは識別子に含めない。ID は英数字・ハイフン・アンダースコアに限定し、任意のパスを受け取らない。
- 「開く」は保存済み問題を優先する。未取得時だけ公開ページを取得する。HTTP は Rust が担当し、リダイレクトを追わず、接続5秒・全体15秒・HTML 4 MiB を上限とする。ログイン・認証情報は扱わない。
- 日本語の問題文を優先し、なければ英語を使う。タイトル・問題文・番号で対応するサンプル入出力を抽出する。サンプル欠落・重複・不正なHTML・上限超過はエラーにする。
- 問題文はテキストとして表示する。数式のTeX表記を保持し、画像は代替テキスト／原文参照表示とする。スクリプトやHTMLを画面へ挿入しない。画像保存・数式の組版は後続の機能。
- 問題文は1 MiB、各サンプル入出力は1 MiB、ケースは1〜100件。保存済み問題JSONは8 MiB、ケースJSONは既存の16 MiBを上限にして読み込む。UTF-8とスキーマを検証する。
- 「再取得」は入力URLの説明・サンプル原本を更新する。選択中と同じ問題なら本文表示も更新する。表示中のコード・ケース・未保存状態は変更しない。未選択・キャッシュ破損時も再取得でき、取得後に「開く」で作業領域を開く。失敗時は以前の問題を保持する。

## 問題の切り替えと編集

- 切替前にソースとケース両方の未保存変更を確認する。拒否、取得失敗、作業領域の読み込み失敗では現在のコード・ケース・保存先を保持する。
- 切替成功時は保存済み作業領域を開き、ケース先頭を選んで結果を消す。既存の `SampleCases.replace(data, { saved: true })` を使う。
- 実行中・ファイル操作中は切替・再取得・保存を重複開始しない。問題の読込中も編集と再読み込みを既存の保護に含める。
- ソースの新規作成・手動読込・別パスへの保存で問題選択を解除し、通常のファイル操作へ戻る。ケースは既存どおり維持する。
- キャッシュ・作業領域の保存は一時ファイル経由。作業領域の初期作成では既存ファイルを置き換えない。取得更新で利用者のファイルを削除しない。

## 受入条件

- URL検証、日本語／英語HTML、番号によるペアリング、空出力、改行・HTMLエンティティ、サイズ制限、不正データをRustで検証する。
- ローカルHTTPで成功・HTTPエラー・リダイレクト・サイズ超過を確認する。普段のテストは外部サービスへ接続しない。
- 一時ユーザーデータ領域でキャッシュ再利用、アトミック更新、保存済みコード・ケースの復元、失敗時の保持を確認する。
- 共通GUIで問題文の安全な表示、サンプル全件実行、作業領域への保存と再表示、未保存確認、最小画面を確認する。
- 80問程度の問題集登録・一括取得・一覧切替は、この1問の保存形式を使って後続で実装する。

## ケースモデル

`SampleCases` は DOM・Tauri・I/Oに依存せず、入力・結果・選択・保存済み状態・リビジョン・実行スナップショットと判定遷移を担当する。renderer は描画・操作と既存の単発実行APIによるキュー制御を担当する。
