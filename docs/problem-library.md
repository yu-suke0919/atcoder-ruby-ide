# AtCoder 問題ライブラリ

## 保存先と責務

Tauri の `app.path().app_local_data_dir()` を使う。Windows では通常 `%LOCALAPPDATA%\io.github.yu-suke0919.atcoder-ruby-ide`。配布フォルダーや一時キャッシュには保存しない。

```text
<app_local_data_dir>/
  library/problems/<contest-id>/<task-id>/problem.json
  library/collections/<contest-id>.json
  library/collections/<contest-id>/<task-id>.json
  workspaces/<contest-id>/<task-id>/solution.rb
  workspaces/<contest-id>/<task-id>/cases.json
```

`library` は取得した問題、`workspaces` は自分の解答とケース。再取得では `problem.json` だけを更新し、解答・編集済みケースは上書きしない。初回に空の解答とサンプルのコピーを作り、再度開くと保存済み解答・ケースを復元する。解答は通常の「保存」、ケースは「ケース保存」でこの作業領域へ保存する。問題選択中に手動でケースJSONを取り込んだ場合は、作業領域の保存済み内容との差分を未保存として扱う。

## 1問の取り込み

- 「AtCoder の問題」ダイアログで `https://atcoder.jp/contests/<contest-id>/tasks/<task-id>` を入力する。クエリ・フラグメントは識別子に含めない。ID は英数字・ハイフン・アンダースコアに限定し、任意のパスを受け取らない。
- 「開く」は保存済み問題を優先する。未取得時だけ公開ページを取得する。HTTP は Rust が担当し、リダイレクトを追わず、接続5秒・全体15秒・HTML 4 MiB を上限とする。ログイン・認証情報は扱わない。
- 日本語の問題文を優先し、なければ英語を使う。タイトルには「解説」などの操作リンクを含めない。問題文と番号で対応するサンプル入出力を抽出する。サンプル見出しが `section` の内側にある現行形式と、外側にある旧形式の両方に対応し、各見出しに続く最初の `pre` を使う。次の見出しまでに本文がない場合やサンプル欠落・重複・上限超過はエラーにする。
- 問題文はテキストとして表示する。数式のTeX表記を保持し、画像は代替テキスト／原文参照表示とする。スクリプトやHTMLを画面へ挿入しない。画像保存・数式の組版は後続の機能。
- 問題文は1 MiB、各サンプル入出力は1 MiB、サンプルは0〜100件。A50「山型足し算」のようにHTML内に通常のサンプル入出力がない問題も本文を保存する。ZIPなど別ファイルのサンプルは取得せず、初回の作業領域には比較無効の空ケースを1件用意する。編集中のケースは従来どおり1〜100件。片方だけのサンプルや欠損はエラーにする。保存済み問題JSONは8 MiB、ケースJSONは既存の16 MiBを上限にして読み込む。UTF-8とスキーマを検証する。
- 「再取得」は入力URLの説明・サンプル原本を更新する。選択中と同じ問題なら本文表示も更新する。表示中のコード・ケース・未保存状態は変更しない。未選択・キャッシュ破損時も再取得でき、取得後に「開く」で作業領域を開く。失敗時は以前の問題を保持する。

## 問題の切り替えと編集

- 切替前にソースとケース両方の未保存変更を確認する。拒否、取得失敗、作業領域の読み込み失敗では現在のコード・ケース・保存先を保持する。
- 切替成功時は保存済み作業領域を開き、ケース先頭を選んで結果を消す。既存の `SampleCases.replace(data, { saved: true })` を使う。
- 実行中・ファイル操作中は切替・再取得・保存を重複開始しない。問題の読込中も編集と再読み込みを既存の保護に含める。
- 問題取得の開始時に文書のリビジョンを記録する。取得中の再読み込みや別ファイルへの切替・保存で文書が更新された場合、古い取得結果から作業領域を開かない。再読み込み後の保存先を遅れて完了した取得処理で変更しない。
- ソースの新規作成・手動読込・別パスへの保存で問題選択を解除し、通常のファイル操作へ戻る。ケースは既存どおり維持する。
- キャッシュ・作業領域の保存は一時ファイル経由。作業領域の初期作成では既存ファイルを置き換えない。取得更新で利用者のファイルを削除しない。

## 問題集の取り込みと固定保存

- 問題集はAtCoderのコンテスト単位。`https://atcoder.jp/contests/tessoku-book` のようなURLを1つ入力する。`/tasks` 付きも同じ問題集として扱う。名前や問題URLを個別入力しない。
- 初回のみ `/contests/<id>/tasks?lang=ja` をHTTPSで取得し、問題集名・表示番号・タイトル・問題URLを公式の掲載順で保存する。各行の2つのリンクを1問として扱い、IDからURLを推測しない。同じコンテストの公開問題だけを許可し、空の一覧・重複・不正URLは拒否する。
- 問題集は最大1,000問、一覧JSONは2 MiB。1問あたりのケース数上限とは別に扱い、tessoku-bookの151問を登録できる。
- 初回登録に続けて本文・サンプルを1問ずつ取得する。取得済みの単問キャッシュがあれば利用し、問題集専用の原本を上書きせず保存する。以後、単問の再取得でも問題集の原本は変わらない。
- 一覧・本文・サンプルを更新する機能や自動同期は設けない。同じURLの再登録は保存済み問題集を開く。起動・表示・問題選択で一覧を再取得しない。
- 取得済み件数と失敗理由を表示する。「中断」は実行中の1問が終わってから残りを停止する。「未取得分を取得」で未取得・失敗分だけを再試行し、取得済みファイルは読み直すだけで通信も上書きもしない。失敗理由と成功した原本は保存し、アプリの再起動後も続きから取得できる。
- 取得キューは画面から1問ずつバックエンドへ依頼し、問題間に500ms空ける。再読み込み・終了で残りのキューは破棄し、実行中の1問だけは保存まで完了できる。Rust側で問題集操作を直列化し、再読み込みをまたぐ重複取得を防ぐ。
- 保存済み問題集を選ぶと、公式順の番号・タイトル・取得状態を表示する。取得済みの問題は問題集原本からオフラインで開き、既存の問題別ワークスペースを復元する。単問用と解答・ケースは共有し、問題集選択中は再取得を無効にする。切替時の未保存確認と文書リビジョンによる保護を維持する。
- 原本が壊れている場合はエラーにし、取得済みファイルを最新サイトの内容で置き換えない。一覧の読み込み失敗や取得失敗で、現在の解答・ケース・保存先を変更しない。

## 受入条件

- URL検証、日本語／英語HTML、番号によるペアリング、空出力、改行・HTMLエンティティ、サイズ制限、不正データをRustで検証する。
- ローカルHTTPで成功・HTTPエラー・リダイレクト・サイズ超過を確認する。普段のテストは外部サービスへ接続しない。
- 実サイトから取得したタイトル・問題本文のHTML抜粋で、現行形式・旧形式と日本語優先を回帰テストする。明示実行する実サイトテストでは `practice_1`・`abc086_a`・`abc001_1` を本番のHTTP処理で取得・再取得し、全サンプルのRuby実行、保存とキャッシュ再利用、編集済み解答・ケースの保持を確認する。
- 一時ユーザーデータ領域でキャッシュ再利用、アトミック更新、保存済みコード・ケースの復元、失敗時の保持を確認する。
- 取得開始後に文書をリセット・切替・保存した場合、古い問題を開こうとしても現在の保存先とファイル内容を保持し、未作成の作業領域も作らないことを確認する。
- 共通GUIで問題文の安全な表示、サンプル全件実行、作業領域への保存と再表示、未保存確認、最小画面を確認する。
- 実ページの固定HTMLで151問の名前・番号・URL・掲載順を検証する。ローカルの取得差し替えで中断・失敗・再開、取得済みの通信スキップ、原本の不変性、単問の再取得との分離を確認する。
- 共通GUIで問題集の登録、再登録、一覧切替、進捗・中断・失敗分の再試行、オフラインでの解答復元、未保存変更の確認、900×650での表示を検証する。

## ケースモデル

`SampleCases` は DOM・Tauri・I/Oに依存せず、入力・結果・選択・保存済み状態・リビジョン・実行スナップショットと判定遷移を担当する。renderer は描画・操作と既存の単発実行APIによるキュー制御を担当する。
