# AtCoder 問題ライブラリ

## 保存先と責務

Tauri の `app.path().app_local_data_dir()` を使う。Windows では通常 `%LOCALAPPDATA%\io.github.yu-suke0919.atcoder-ruby-ide`。配布フォルダーや一時キャッシュには保存しない。

```text
<app_local_data_dir>/
  library/problems/<contest-id>/<task-id>/problem.json
  library/collections/<contest-id>.json
  library/collections/<contest-id>/<task-id>.json
  workspaces/<contest-id>/<task-id>/solution.rb
  workspaces/<contest-id>/<task-id>/cases.json
```

`library` は取得した問題、`workspaces` は自分の解答とケース。再取得では `problem.json` だけを更新し、解答・編集済みケースは上書きしない。初回に空の解答とサンプルのコピーを作り、再度開くと保存済み解答・ケースを復元する。解答は通常の「保存」、ケースは「ケース保存」でこの作業領域へ保存する。問題選択中に手動でケースJSONを取り込んだ場合は、作業領域の保存済み内容との差分を未保存として扱う。

## 保存形式を変えるときの方針

保存形式の変更とは、保存データの項目・型・構造・値の意味を変えること。一括復旧が必要かは「変更前の仕様で有効だった保存データを、変更後も同じ意味で読み込めるか」で判断する。同じ意味で読める変更には、一括復旧やケースの作り直しを求めない。[開発ルール](../AGENTS.md)の後方互換・移行を追加しない方針は維持する。

| 変更の例 | 既存データ | 一括復旧 |
| --- | --- | --- |
| 時間制限を任意項目で追加し、未設定は「不明」とする | 同じ意味で読める | 不要 |
| 誤差許容を任意項目で追加し、未設定は従来の厳密比較とする | 同じ意味で読める | 不要 |
| 必須項目の追加、項目名・型・構造の変更により既存データを読めなくする | 読めない | 必要 |
| 値の意味の変更（秒→ミリ秒など） | 読めても解釈が変わる | 必要 |

表の「必要」は、一括復旧の対象である問題集の固定原本、または作り直しが必要なケースに影響する場合に適用する。単問キャッシュは一括復旧の対象外とし、読めなければ既存の「再取得」を案内する。

値の意味を変える場合は、項目名を変えるなどして意味が変わる旧データを通常の現行形式として受理しないようにし、そのうえで復旧手段を用意する。項目名・型が同じまま単位だけ変えて、旧値を黙って新しい意味で読み込ませない。

### 任意項目を追加する条件

- 未設定の意味を現行仕様として資料に定め、新しく保存するデータでも未設定を有効な状態として扱う。例えば、未設定をNoneとして読むOption項目の追加は、この条件と冒頭の判断基準を満たせば一括復旧を必要としない。
- 互換のためだけに必須項目を省略可能にしたり、未知項目を無視したり、必須項目を既定値で補完したりしない。未知の項目・型・必須項目・範囲の厳密な検証を維持する。
- 一括復旧が不要でも、単問キャッシュ、問題集の一覧と固定原本、作業領域のケース、利用者が別途保存したケースJSONの影響範囲と、未設定の意味を資料に記す。Problemだけでなく、statementや共有するSampleCaseの変更も確認する。
- 追加項目を含まない既存形式の固定データが、定めた未設定の意味で読めることを回帰テストで確認する。利用者のケースでは従来と同じ判定・表示になることも確認する。

### 一括復旧が必要な変更の条件

以下は、上記の判断基準で一括復旧が必要となる変更に適用する。この方針は将来の変更PRの条件であり、現在の保存形式や取得操作を変更するものではない。

- 変更前に、影響範囲と復旧対象を資料に記す。一括復旧の対象は問題集の固定原本と、作り直しが必要な利用者のケースに絞る。単問キャッシュは前述の再取得案内で足りる。
- 問題集は1問ずつの「取り直す」だけで済ませず、原本が存在していても旧形式で読めない複数問をまとめて対象にできる手段を同じPRに含める。一覧の形式も変える場合は、原本の復旧に必要な問題URLを確定する手段を含める。既存の「同じURLの再登録で、読めない一覧だけを取り直す」動作で足りる場合はそれを使い、重複する復旧機能を追加しない。
- 一括復旧は利用者の明示操作とする。対象と、現在のAtCoderの内容で原本を置き換えるため保存時と異なる内容になる可能性を操作前に示す。起動・表示時の自動更新にはしない。正常な固定一覧は、形式変更で復旧が必要な場合を除いて更新しない。
- 原本は1問ずつ取得・検証後にアトミックに置き換える。通信・解析・保存に失敗した問題の以前のファイルは保持する。一部の成功後に失敗・中断した場合も、残る対象が分かり再試行できるようにする。一括処理全体の巻き戻しは求めない。
- 原本の取り直しでsolution.rbや編集済みcases.jsonを上書き・削除せず、編集中の解答・ケース・保存先も切り替えない。ケースの作り直しが必要な場合は、[ケースJSONの変更方針](multi-sample.md#ケースjsonの形式を変えるとき)に従う。再取得したサンプルを利用者の編集内容の代わりに保存しない。
- 一括復旧が必要な変更PRには旧形式の固定データを使った回帰テストを含める。複数の保存済み原本の一括復旧、確認の拒否、途中の失敗・中断と再試行、利用者データの保持を確認する。Linux・Windowsの全テストとWindows配布検証がPRのCIで成功してから採用する。

## 問題の制限値

- 公開問題ページの本文直前にある「実行時間制限 / メモリ制限」（英語はTime Limit / Memory Limit）を取得し、問題文パネルのタイトル下に表示する。時間はsec（小数第3位まで）、メモリは整数MiBを受け入れる。記載のない値は「不明」とし、記載があるのに単位・値が不正な場合や重複する場合は取得を失敗させ、保存済み原本を保持する。問題本文中の同名の語は制限値として扱わない。
- Problemの任意項目timeLimitMs（ミリ秒）とmemoryLimitMiB（MiB）として保存する。値は1〜4,294,967,295の整数、省略またはnullは「不明」。新たに取得したページでも記載がなければ未設定を有効とし、推測値で補完しない。未知項目・不正な型・範囲は引き続き拒否する。
- 影響範囲は単問キャッシュと問題集の固定原本。追加項目のない保存済み問題も同じ意味で読み込み、「不明」と表示するため一括復旧は不要。問題集の一覧、solution.rb、作業領域のcases.json、手動保存のケースJSONと共有SampleCaseは変更しない。制限値を取り込むときは既存の再取得・1問取り直しを使い、保存済み問題を自動更新しない。
- 実行開始時の時間制限をケースごとに保持し、実測時間がその値を超えたら結果欄に「制限超過の可能性」と比較した制限値を表示する。正常終了・エラー終了・5秒の打ち切り・出力上限の結果を対象にし、手動停止・起動失敗・未実行・制限不明では表示しない。同値なら超過としない。実測時間はRubyの起動や入出力処理も含む経過時間で、AtCoderの判定や性能を再現するものではない。
- 注意表示は期待出力との一致・不一致と別に扱い、5秒の実行打ち切りとメモリを制限しない方針を維持する。全件実行では開始時の制限値を全ケースへ適用する。再取得で制限値が変わっても完了済み結果は実行時の値で保持し、次の実行から新しい値を使う。ソース・作業ディレクトリの変更は全ケース、入力・期待出力・比較設定の変更は該当ケースの注意表示を消す。実行中の編集後に古い注意表示を復活させない。注意表示と実行時の制限値はケースJSONには保存しない。
- 固定データで日本語・英語の抽出、小数の時間、未設定、不正な値・単位・重複、追加項目のない単問キャッシュと固定原本のオフライン読込を確認する。ケースごとの注意表示、境界値、編集・再取得・停止・再実行、900×650と3列配置を両OSのGUIで確認する。

## 1問の取り込み

- 「AtCoder の問題」ダイアログで `https://atcoder.jp/contests/<contest-id>/tasks/<task-id>` を入力する。クエリ・フラグメントは識別子に含めない。ID は英数字・ハイフン・アンダースコアに限定し、任意のパスを受け取らない。
- 「開く」は保存済み問題を優先する。未取得時だけ公開ページを取得する。HTTP は Rust が担当し、リダイレクトを追わず、接続5秒・全体15秒・HTML 4 MiB を上限とする。ログイン・認証情報は扱わない。
- 日本語の問題文を優先し、なければ英語を使う。タイトルには「解説」などの操作リンクを含めない。問題文と番号で対応するサンプル入出力を抽出する。サンプル見出しが `section` の内側にある現行形式と、外側にある旧形式の両方に対応し、各見出しに続く最初の `pre` を使う。次の見出しまでに本文がない場合やサンプル欠落・重複・上限超過はエラーにする。
- 問題文はテキスト・数式・コード例・画像の順序付きデータとして保存し、アプリが表示要素を組み立てる。数式は同梱KaTeXで整形し、画像も保存してオフライン表示する。スクリプトや取得HTMLを画面へ挿入しない。詳細は[数式と画像の仕様](problem-presentation.md)を参照する。
- 問題URLの入力・取得はダイアログで行い、開くことに成功したら閉じて常設の問題文パネルを表示する。問題集から開く場合も同じパネルを使う。拒否・取得失敗・作業領域の読込失敗では選択ダイアログを残し、現在の問題・表示状態・編集内容を保持する。
- 問題文は1 MiB、各サンプル入出力は1 MiB、サンプルは0〜100件。A50「山型足し算」のようにHTML内に通常のサンプル入出力がない問題も本文を保存する。ZIPなど別ファイルのサンプルは取得せず、初回の作業領域には比較無効の空ケースを1件用意する。編集中のケースは従来どおり1〜100件。片方だけのサンプルや欠損はエラーにする。保存済み問題JSONは画像を含め32 MiB、ケースJSONは既存の16 MiBを上限にして読み込む。UTF-8とスキーマを検証する。
- 「再取得」は入力URLの説明・サンプル原本を更新する。選択中と同じ問題なら本文表示も更新する。表示中のコード・ケース・未保存状態は変更しない。未選択・キャッシュ破損時も再取得でき、取得後に「開く」で作業領域を開く。失敗時は以前の問題を保持する。

## 問題の切り替えと編集

- 問題文パネルを表示したままコード・ケースの編集、保存、実行、停止とショートカットを使える。本文は独立してスクロールでき、取得HTMLは挿入せず、テキスト・数式・画像の表示要素を組み立てる。選択中の問題を表示元とし、パネル操作で通信しない。
- 「問題文を隠す／表示する」で表示を切り替える。非表示時はコード領域を広げ、切替ではコード・ケース・実行結果・未保存状態・保存先と本文のスクロール位置を保持する。問題を開くと自動表示し、別問題に切り替わる場合は本文を先頭へ戻す。通常ファイルへの切替で問題選択を解除したら非表示にする。表示設定は永続化しない。
- 幅1,200px以上で問題文・コード・入出力の3列にする。狭い画面では左上に問題文、左下にコード、右にサンプルと結果を置く。900×650でも本文とコードを同時に読み、各領域内のスクロールと実行・停止を利用できる。本文を隠すと従来の2列に戻す。
- 再取得と確認付きの個別取り直しは、選択中の対象の本文だけをパネルに反映する。非表示状態を勝手に変更せず、コード・ケース・結果を置き換えない。
- 切替前にソースとケース両方の未保存変更を確認する。拒否、取得失敗、作業領域の読み込み失敗では現在のコード・ケース・保存先を保持する。
- 切替成功時は保存済み作業領域を開き、ケース先頭を選んで結果を消す。既存の `SampleCases.replace(data, { saved: true })` を使う。
- 実行中は問題の切替・再取得・ソースの初回保存・名前を付けて保存・ケースの保存／読込を開始しない。同じパスへのソースの上書き保存は可能。ファイル操作中は切替・再取得・保存を重複開始しない。問題の読込中も編集と再読み込みを既存の保護に含める。
- 問題取得の開始時に文書のリビジョンを記録する。取得中の再読み込みや別ファイルへの切替・保存で文書が更新された場合、古い取得結果から作業領域を開かない。再読み込み後の保存先を遅れて完了した取得処理で変更しない。
- ソースの新規作成・手動読込・別パスへの保存で問題選択を解除し、通常のファイル操作へ戻る。ケースは既存どおり維持する。
- キャッシュ・作業領域の保存は一時ファイル経由。作業領域の初期作成では既存ファイルを置き換えない。取得更新で利用者のファイルを削除しない。

## 問題集の取り込みと固定保存

- 問題集はAtCoderのコンテスト単位。`https://atcoder.jp/contests/tessoku-book` のようなURLを1つ入力する。`/tasks` 付きも同じ問題集として扱う。名前や問題URLを個別入力しない。
- 初回のみ `/contests/<id>/tasks?lang=ja` をHTTPSで取得し、問題集名・表示番号・タイトル・問題URLを公式の掲載順で保存する。各行の2つのリンクを1問として扱い、IDからURLを推測しない。同じコンテストの公開問題だけを許可し、空の一覧・重複・不正URLは拒否する。
- 問題集は最大1,000問、一覧JSONは2 MiB。1問あたりのケース数上限とは別に扱い、tessoku-bookの151問を登録できる。
- 初回登録に続けて本文・サンプルを1問ずつ取得する。単問キャッシュを経由せず通信で取得し、問題集専用の原本を上書きせず保存する。以後、単問の再取得でも問題集の原本は変わらない。
- 一覧の更新や問題集全体の更新・自動同期は設けない。同じURLの再登録は保存済み問題集を開く。起動・表示・問題選択で一覧を再取得しない。
- 取得済み件数と失敗理由を表示する。「中断」は実行中の1問が終わってから残りを停止する。「未取得分を取得」で未取得・失敗分だけを再試行し、取得済みの問題はキューから除外して通信も上書きもしない。取得状態は原本ファイルの存在で判定し、通常の再開では取得済み原本の内容を読み直して検証しない。原本は問題を開くときに読み込み・検証する。失敗理由と成功した原本は保存し、アプリの再起動後も続きから取得できる。
- 取得キューは画面から1問ずつバックエンドへ依頼し、問題間に500ms空ける。再読み込み・終了で残りのキューは破棄し、実行中の1問だけは保存まで完了できる。Rust側で問題集操作を直列化し、再読み込みをまたぐ重複取得を防ぐ。
- 保存済み問題集を選ぶと、公式順の番号・タイトル・取得状態を表示する。取得済みの問題は問題集原本からオフラインで開き、既存の問題別ワークスペースを復元する。単問用と解答・ケースは共有し、問題集選択中は再取得を無効にする。切替時の未保存確認と文書リビジョンによる保護を維持する。
- 通常の取得や再試行では、原本が壊れていても取得済みファイルを上書きしない。一覧の読み込み失敗や取得失敗で、現在の解答・ケース・保存先を変更しない。

### 確認付きの個別取り直し

- 取得済みの各行に「取り直す」を設ける。原本の欠落箇所や破損を修復するための明示操作とし、自動取得・未取得分の再試行からは呼ばない。未取得の行は無効にする。
- 操作前に問題集名・問題番号・タイトル・URLを示し、現在のAtCoderの内容で原本を置き換えること、保存時と異なる内容になる可能性、解答・編集済みケースを保持することを確認する。キャンセル・Escでは通信も保存も開始しない。
- 確認後、同じ問題集に含まれる対象1問だけをHTTPSで取得する。単問キャッシュと壊れた原本は読み込まず、新しいHTMLを解析・検証してから対象原本を一時ファイル経由で置き換える。取得・解析・保存の失敗時は以前の原本を残す。
- 問題集名・問題一覧・他の原本・単問キャッシュ・解答・編集済みケースは変更しない。対象を表示中なら問題文とサンプル原本の表示だけを更新し、現在のコード・ケース・結果・未保存状態・保存先を保持する。表示していない問題の取り直しでは現在の問題表示を変えない。
- 問題集の登録・取得と同じRustのMutexで直列化し、実行・取得・ファイル操作中は開始できない。取り直し中の再読み込みでも文書の保存先を変更しない。

## 受入条件

- URL検証、日本語／英語HTML、番号によるペアリング、空出力、改行・HTMLエンティティ、サイズ制限、不正データをRustで検証する。
- ローカルHTTPで成功・HTTPエラー・リダイレクト・サイズ超過を確認する。通常の自動テストではAtCoderへ接続しない。
- 実サイトから取得したタイトル・問題本文のHTML抜粋で、現行形式・旧形式と日本語優先を回帰テストする。明示実行する実サイトテストでは `practice_1`・`abc086_a`・`abc001_1` を本番のHTTP処理で取得・再取得し、全サンプルのRuby実行、保存とキャッシュ再利用、編集済み解答・ケースの保持を確認する。
- 一時ユーザーデータ領域でキャッシュ再利用、アトミック更新、保存済みコード・ケースの復元、失敗時の保持を確認する。
- 取得開始後に文書をリセット・切替・保存した場合、古い問題を開こうとしても現在の保存先とファイル内容を保持し、未作成の作業領域も作らないことを確認する。
- 共通GUIで問題文の安全な表示、サンプル全件実行、作業領域への保存と再表示、未保存確認、最小画面を確認する。
- 実ページの固定HTMLで151問の名前・番号・URL・掲載順を検証する。ローカルの取得差し替えで中断・失敗・再開、取得済みの通信スキップ、原本の不変性、単問の再取得との分離を確認する。
- 共通GUIで問題集の登録、再登録、一覧切替、進捗・中断・失敗分の再試行、オフラインでの解答復元、未保存変更の確認、900×650での表示を検証する。
- 個別取り直しでは確認・キャンセル・Esc、対象1問だけの修復、通信とHTML検証の失敗保護、破損原本からの復帰、表示中の未保存変更と結果の保持を確認する。
- 常設パネルでは単問・問題集の両方で開いた後に選択ダイアログが閉じること、本文を表示したまま編集・保存・実行できること、非表示の切替と再取得で未保存内容・結果・本文スクロールを保持することを確認する。長い本文、3列と上下配置、900×650と大きな行高、選択の拒否・失敗と通常ファイルへの切替も確認する。

## ケースモデル

`SampleCases` は DOM・Tauri・I/Oに依存せず、入力・結果・選択・保存済み状態・リビジョン・実行スナップショットと判定遷移を担当する。renderer は描画・操作と既存の単発実行APIによるキュー制御を担当する。

## 取得の障害と操作の独立性

問題集の未取得問題と個別取り直しは、単問キャッシュを経由せず通信で本文・画像を取得する。単問キャッシュへの書き込みも行わない。壊れた単問キャッシュは問題集の取得を妨げない。問題集一覧では不正なJSONや名前のマニフェストを読み飛ばし、正常な問題集を引き続き表示する。一覧表示では読み飛ばしたファイルを削除・上書きしない。同じURLの再登録ではマニフェスト自体を読み込み・検証できない場合だけ、公開ページから一覧を取得・検証してマニフェストをアトミックに置き換える。原本の存在確認でI/Oエラーが起きても、正常なマニフェストや保存済み失敗理由は置き換えずエラーを返す。通信・解析に失敗した場合は元のマニフェストを保持する。取得済みの問題原本・解答・ケースは保持し、復旧後の一覧に含まれる原本をファイルの有無で再利用する。

一括取得の状態は文書操作と独立して管理する。取得中もダイアログを閉じて編集・実行できる。同時の登録・再開・問題集切替・個別取り直しは無効とし、中断は現在の1問が完了してから反映する。

問題集の登録・取得の進捗とエラーは問題集ダイアログ内だけに表示し、実行結果のメッセージを上書きしない。実行中も問題集ダイアログを開いて取得状況の確認・中断ができる。登録・再開・切替・問題を開く・取り直す操作は実行中には無効にする。

問題集ダイアログには、保存済み問題集が一覧に出ない場合に同じURLでの再登録を試す案内を常設する。読み飛ばした件数を返すAPIや追加の状態管理は設けない。
