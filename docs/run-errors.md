# 実行エラーからコードへ移動

実行後の構文エラー・実行時エラーから、現在のコードの該当行へ移動できるようにする。

- RustのRunnerが、異常終了時の確定したstderrから実行した一時ソースの絶対パスに一致する最初の行番号を抽出し、RunResultの `errorLine` に返す。ライブラリ内で発生したエラーも、実行コードの呼び出し元があればその行を使う。
- Rubyの `パス:行番号:` と `from パス:行番号:` を対象とし、Windowsのパス区切りにも対応する。他のファイル・本文中に現れるパス・範囲外の行番号は採用しない。位置を判定できなければnullとし、stderrはそのまま表示する。正常終了、停止、時間制限、出力制限、起動失敗にはジャンプを付けない。
- ケース別に行番号を保持する。標準エラー欄の「コードの○行目へ」をクリックまたはキーボードで操作すると、コード欄へフォーカスし、その行の先頭へ移動してスクロールする。エラー行を背景色で強調し、列番号は推測しない。
- ジャンプでコード・未保存判定・比較結果を変更しない。同じファイルへの保存、問題文の表示切替・更新でも位置を保持する。ファイル操作・終了確認中はジャンプ操作を禁止する。
- コード・ケース入力・期待出力・比較設定・保存先が変わったら古い位置と強調を解除する。実行中に編集された場合も、古い実行の完了で位置を復活させない。Undoで元のコードへ戻しても、再実行までは解除したままにする。
- 再実行の開始、結果クリア、文書・問題の切替でも古い位置を解除する。行番号はケースJSONやワークスペースへ保存しない。
- Rubyコードを実行する既存の処理と出力上限を利用し、編集時の自動構文チェックや任意ファイルのオープンは行わない。

実Rubyの構文・実行時・ライブラリエラー、誤ったパス・行番号、異常終了以外の位置抑止をRustで検証する。ケースごとの保持・失効・遅延した完了をNodeで、ジャンプ・強調・スクロール・保存・編集・切替・最小画面をLinuxとWindowsの共通GUIテストで確認する。
