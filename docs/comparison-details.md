# 最初の不一致箇所

比較処理の API と、不一致の行・列・期待値・実際値を確認する画面を提供する。

## API と比較ルール

- `first_difference(actual, expected, tolerance)` は一致時に `None`、不一致時に `OutputDifference` を返す。toleranceがNoneなら厳密比較とする。
- `OutputDifference` は `line`・`column`（実際値）・`expected_column`（期待値）・`actual_line`・`expected_line` を持つ。最初に異なる行だけを返し、行の中では許容されない最初の文字を指す。
- 行・列は 1 始まり。列は Unicode スカラー値の数で数える。日本語や `😀` は各 1 列、タブも 1 列とし、結合文字・ZWJ は個別に数える。画面上の幅や UTF-8 バイト位置ではない。
- 既存の一致判定と同じく、CRLF / CR を LF にし、末尾の LF を最大 1 つ除く。それ以外の空白・空行・大文字小文字・数値表記は区別する。
- 各行の値は正規化後の内容で、改行を含まない。空の行は `Some("")`。空出力も先頭の空行として扱い、途中から行が足りない場合は、その側を `None` として列 1 を返す。
- 行内で片方が先に終わる場合は、それぞれの側の対応する終端列を指す。厳密比較では共通部分の文字数+1となる。
- 一致判定は `first_difference(...).is_none()` に統一する。比較ルールを維持し、追加ライブラリ・全差分生成・前後の行の対応付けは導入しない。

### 誤差許容

- εが設定されているときだけ、空白で区切られたトークン全体を有限のf64として解釈できる両側の数値を比較する。符号・小数・指数表記を受け入れる。NaN・Infinity・f64の範囲外を含むその他のトークンは従来の文字比較とする。数値の精度はf64の精度による。
- 整数表記も数値として扱うため、ε=1e-6では実際値1000001と期待値1000000が一致する。2^53を超える整数ではf64で異なる整数を区別できない場合もある。整数の完全一致が必要な問題は既定の厳密比較を使う。浮動小数点の値が整数表記で出力されることもあるため、表記だけで整数用の規則へ自動切替はしない。
- 絶対誤差がε以下、または期待値の絶対値を基準にした相対誤差がε以下なら一致とする。期待値0は絶対誤差のみで比べる。同値・境界は一致とし、ε自体は保存・実行の受付で正の有限数か検証する。差や比のオーバーフローで誤って一致としない。
- CRLF / CRの正規化と末尾LFを最大1つ除く規則は維持する。トークン間の空白・タブ・改行を省略・統合せず、数値以外の内容は厳密に比較する。
- 許容した数値の表記の長さが違う場合も、実際値と期待値の列をそれぞれ数える。例えば実際値 `0.500 日😀A` と期待値 `0.5 日😀B` は数値を許容した後、実際値9列・期待値7列を不一致として示す。行番号は共通で、列はUnicodeスカラー値を数える。
- 許容されない数値や文字列はトークン内の最初に異なる文字を示す。空白の違いはその空白を示し、行の過不足・空行・行末の意味は維持する。

| 実際値 | 期待値 | 最初の不一致 |
| --- | --- | --- |
| `6 test\n` | `6 tast\n` | 1 行 4 列、`6 test` / `6 tast` |
| `日😀A` | `日😀B` | 1 行 3 列 |
| `ok ` | `ok` | 1 行 3 列、末尾の空白 |
| `ok` | `ok\n\n` | 2 行 1 列、実際の行なし / 期待する空行 |
| `a\r\nb\r\n` | `a\nb` | 一致 |

## 受入条件と進め方

資料 → 失敗するテスト → 最小実装 → 不要コード・資料矛盾の確認の順に進める。
比較アルゴリズムは comparison モジュールの単体テスト、Runner・IPC の契約は contract テスト、画面は共通 E2E で確認する。

- 一致時は詳細を返さず、複数箇所が異なる場合は先頭だけを返す。
- 先頭・途中・末尾の差、行の過不足、空出力、空行、空白、タブを検証する。
- 日本語・絵文字・結合文字と、改行正規化後の行番号・文字列を確認する。
- 既存の一致判定と詳細の有無が一致し、1 MiB の長い行でも最初の位置を特定できる。
- 共通テスト・既存 UI テストと、Windows の配布検証を通す。

## UI・IPC

- `OutputDifference` は `Clone`・serde::SerializeとcamelCaseに対応し、RunResult.differenceでactualLine・expectedLine・expectedColumnを送る。差分は保存データではないため、`task.json`・`samples.json`の形式には影響しない。
- Runner は正常終了・比較有効のときだけ `first_difference` を 1 回呼び、その結果から `comparison` も導く。比較無効・エラー・停止時は両方 null、一致時は `comparison: true`・`difference: null` とする。
- 結果欄の「不一致」を押すと詳細ダイアログを表示する。1始まりの行・列、期待値・実際値を示し、それぞれの列で強調する。列が同じなら従来の見出し、違うなら両側の列を表示する。
- 半角空白は `␠`、全角空白は `□`、タブは `⇥` として表示する。空行・行なし・行末はそれぞれ `（空行）`・`（行なし）`・`（行末）` と明記する。
- 強調する空白・タブには名称も添え、実際の記号文字と区別する（例：`␠（半角空白）`）。
- Unicode スカラー値で位置を合わせ、表示は差の前後最大 40 文字に絞る。省略部分を `…` とし、長い 1 行でも全体を DOM に展開しない。本文は HTML として解釈しない。
- ダイアログは閉じるボタンまたは Escape で閉じる。1280×720 と大きな行高でも本文をスクロールでき、背後の入力・結果・実行ボタンのレイアウトを変えない。
- 詳細はサンプル別に保持する。サンプルの編集・比較設定・クリアではそのサンプル、コード・実行するファイル・許容誤差の変更では全サンプルを無効にする。新しい実行でも古い詳細を消し、リビジョンが違う結果では復活させない。
- 自動保存では判定と詳細を保持する。詳細は`samples.json`に保存しない。

## UI・IPC の受入条件

資料 → 失敗するテスト → 最小実装 → 不要コード・資料矛盾の確認の順で進める。

- Rust の実 Ruby 実行から比較と詳細を返し、camelCase・null・空文字列・Unicode のシリアライズを確認する。
- 一致・比較無効・実行エラー・手動停止・時間制限・出力上限では詳細を表示しない。
- 本番画面と実 Ruby を通し、Unicode、空白・空行・行不足、長い行、HTML 文字列、サンプル切替、再実行・クリア・保存、実行中編集の無効化を確認する。
- 最小画面と大きな行高、キーボードの開閉、Windows WebView2 と NSIS の配布検証を行う。
