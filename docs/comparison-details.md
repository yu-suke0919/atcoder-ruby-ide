# 最初の不一致箇所

比較処理の API を提供する。画面・IPC・RunResult への接続は後続の変更で行う。

## API と比較ルール

- `first_difference(actual, expected)` は一致時に `None`、不一致時に `OutputDifference` を返す。
- `OutputDifference` は `line`・`column`・`actual_line`・`expected_line` を持つ。最初に異なる行だけを返し、行の中では最初に異なる文字を指す。
- 行・列は 1 始まり。列は Unicode スカラー値の数で数える。日本語・絵文字もそれぞれ 1 文字で、タブは 1、結合文字は個別に数える。画面上の幅や UTF-8 バイト位置ではない。
- 既存の一致判定と同じく、CRLF / CR を LF にし、末尾の LF を最大 1 つ除く。それ以外の空白・空行・大文字小文字・数値表記は区別する。
- 各行の値は正規化後の内容で、改行を含まない。空の行は `Some("")`。空出力も先頭の空行として扱い、途中から行が足りない場合は、その側を `None` として列 1 を返す。
- 行内で片方が先に終わる場合は、共通部分の文字数 + 1 を列にする。
- 既存の `compare_output` の真偽値と実行時の比較動作を維持する。正規化を共有し、追加ライブラリ・全差分生成・前後の行の対応付けは導入しない。

| 実際値 | 期待値 | 最初の不一致 |
| --- | --- | --- |
| `6 test\n` | `6 tast\n` | 1 行 4 列、`6 test` / `6 tast` |
| `日😀A` | `日😀B` | 1 行 3 列 |
| `ok ` | `ok` | 1 行 3 列、末尾の空白 |
| `ok` | `ok\n\n` | 2 行 1 列、実際の行なし / 期待する空行 |
| `a\r\nb\r\n` | `a\nb` | 一致 |

## 受入条件と進め方

資料 → 失敗するテスト → 最小実装 → 不要コード・資料矛盾の確認の順に進める。
単体テストは comparison モジュール内に置き、PR #7 の contract テストと変更箇所を分ける。

- 一致時は詳細を返さず、複数箇所が異なる場合は先頭だけを返す。
- 先頭・途中・末尾の差、行の過不足、空出力、空行、空白、タブを検証する。
- 日本語・絵文字・結合文字と、改行正規化後の行番号・文字列を確認する。
- 既存の一致判定と詳細の有無が一致し、1 MiB の長い行でも最初の位置を特定できる。
- 共通テスト・既存 UI テストと、Windows の配布検証を通す。

## UI・IPC 接続時の扱い

現在の Runner は `compare_output` だけを 1 回呼ぶため、二重正規化は発生していない。
真偽値判定を `first_difference(...).is_none()` へ委譲すると、不一致行のコピーも発生するため、詳細を使わない現在の経路は維持する。

詳細を RunResult に含める変更では、以下をまとめて実装する。

- `OutputDifference` に `Clone`・`serde::Serialize` と `#[serde(rename_all = "camelCase")]` を付け、`actualLine`・`expectedLine` として送る。
- 正常終了・比較有効のときだけ `first_difference` を 1 回呼び、その結果から一致判定も導く。`compare_output` と別々には呼ばない。
- 比較無効・エラー・停止時の `comparison: None` を維持し、空の期待出力と比較無効を区別する。
