# 手元での確認

クラウドセッションやCIでは確かめられず、PRの本文で利用者の手元での確認を求めた項目のうち、結果を[検証記録](verification.md)に書いていないものの一覧。2026-11-14（main 4ce9a33、PR #82まで）の時点で、PR #58〜#82の本文と検証記録を突き合わせて作った。結果を記録済みなのはU5c、U5aの確認3、D3（最終版を除く）だけだった。

確かめたら、結果（確認に使ったコンテストと日時を含む）を検証記録の該当する節に書き、この一覧から項目を消す。期待どおりでなかった項目は、ロードマップに直す項目として加える。新しいPRで手元の確認を求めるときは、PRの本文に書いたうえでこの一覧にも加える。

## 開始時刻に確かめるもの

開催中のコンテストの挙動は開催中にしか確かめられない（[ロードマップ](roadmap.md#守ること)）。アプリのブラウザで開催予定のABCに参加登録し、そのアイコンを選んで、アプリを開いたまま開始を待てば、上から順にまとめて確かめられる。

- U6a（PR #65）：参加登録の検知
  - [ ] ログインした状態で、まだ参加登録していないコンテストのトップを右端のブラウザで開いても、アイコンが増えない。
  - [ ] そのページで参加登録すると、「参加登録しました。」の後にアイコンが加わる。
  - [ ] 開始前にそのアイコンを選ぶと、問題一覧の列に開始の時刻が出る。
- U6c（PR #69）：開始1分前の通知
  - [ ] 開始1分前に、一番上のバーに「<名前>があと1分で始まります（開始 HH:MM）」が出る。
  - [ ] 別のウィンドウを前面にしていると、タスクバーのアイコンが点滅する。
- U6b（PR #66）：開始時に問題一覧を取得して最初の問題を開く
  - [ ] アイコンを選んだまま開始を迎えると、数秒以内に問題一覧が並び、A問題が開いて右端にA問題のページが出る。開始直後で一覧がまだ見られないときは、5秒ごとに取り直す。
  - [ ] 開始時刻に、U6cの案内が消える。
  - [ ] （任意）別のコンテストやホームで問題を編集しながら開始を迎えると、編集内容が保存されたうえでA問題に切り替わる。
- U6a（PR #65）：開始後
  - [ ] 開始時刻にアプリを閉じていた別のコンテストで、開始後にアプリを起動してアイコンを選ぶと、問題一覧が取得されて並ぶ（起動中に開始を迎えたコンテストはU6bで自動で開く）。
  - [ ] 開催中のコンテストのトップで、開始後も「(Contestant)」と表示されている。
  - [ ] （任意）終了から1日たった後にアプリを起動すると、そのアイコンが非表示になる。

## ログインと提出が要るもの

どのコンテストでも確かめられる。

- U5a（PR #64）：提出結果と問題一覧の色
  - [ ] 問題を提出すると、提出一覧へ移ったところで、その問題がジャッジ中の色（灰色で点滅）になる。
  - [ ] 提出一覧を表示したまま待つと、判定が出たところで緑（AC）か黄（AC以外）に変わる。
  - [ ] アプリを開き直しても、色が残っている。
- U5b（PR #68）：ジャッジ中に提出一覧から離れた場合
  - [ ] 提出し、ジャッジ中のあいだにすぐ別の問題を開く。判定が出てから10秒ほど以内に、提出した問題の色が判定の結果に変わる。

## Windowsのアプリで確かめるもの

コンテストは要らない。

- F0（PR #74）：エージェントの準備中に閉じる
  - [ ] `wsl --unregister AtCoderRubyIDE`の後にアプリを起動し、Linuxのダウンロード中にウィンドウを閉じられる。
- F5（PR #79・#80）：画面とRustの分割
  - [ ] るりまの窓とグラフの窓の開閉・切り替え。
  - [ ] 設定のダイアログ（全サンプル一致のコピーのオン・オフ、ドメインの追加・削除）。
  - [ ] 右クリックの「るりまを全文検索」（エディタとAtCoderのページ）。
  - [ ] るりまの窓を出したときの、背景のAtCoderのページの画像。
- D4（PR #72）：グラフ・木の表示
  - [ ] グラフの窓の見た目と、ホイールでの拡大・縮小、背景のドラッグでの移動、頂点のドラッグ、「全体表示」。
- D3（PR #71）：るりまの全文検索
  - [ ] 最後の確認の後に、検索語を`<語> site:docs.ruby-lang.org`に戻し、3.4以外の版のページを3.4のページで開くようにした。`有理数`で検索し、結果から3.4のページが開く。
- D2（PR #70）：読み込みのコードの対応形式
  - [ ] （任意）複数のテストケースの問題（例：ABC460 B）を初めて開くと、`t = gets.to_i`と`t.times do`の中に各テストケースの読み込みが入る。
- R6〜R9（PR #67）
  - [ ] 小数を含む問題（例：ABC169 C）を新しく開くと、最初のファイルに`a, b = gets.split`と`a = a.to_i`が入る。
  - [ ] ホームで誤差許容を0にして保存に失敗させ、タブを切り替えて「破棄して続ける」を選ぶと、誤差許容が元に戻り「保存に失敗しました」が消える。
- D1（PR #60）：入力中の補完
  - [ ] `whil`と打つと、何も押さなくても候補が開き、Enterで改行になる。
  - [ ] `whil`と打ってすぐTabを押すと、一番上の候補（`while`）が入る（速く打っても入る）。
  - [ ] `↓`で候補を選んでからEnterかTabを押すと、選んだ候補が入る。
  - [ ] 候補が開いていないとき（行頭など）のTabは字下げになる。
  - [ ] `a = gets.split.map(&:to_i)`のあとに`a.`と打つと、メソッドの候補が開く。
  - [ ] `end`と打ってEnterを押すと、普通に改行される。
  - [ ] 文字を打つたびに候補が開いても、入力が遅くならない。
- R1〜R4（PR #61）
  - [ ] 問題のタブを切り替えた直後に続けて入力しても、入力が消えない（切り替えの間は入力できないのが正しい）。
  - [ ] 問題を選んですぐ別のコンテストのアイコンを押しても、選んだ問題が開き、その問題に保存される。
  - [ ] 誤差許容を0にして保存に失敗した後、チェックを外すと「保存済み」に戻る。
